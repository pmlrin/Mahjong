## 1. 目标与当前基础

用户指定本版完成四项牌桌操作能力，先编写说明文档。目标是在保留原有选牌确认方式的基础上，让熟练玩家减少重复操作，并为电脑端提供完整的键盘路径。

当前核对的源码版本为 `0.4.1`。按现有代码与记录，V4 账号、好友和邀请，以及 V4.1 上传头像、简明玩法与 42 役图鉴已实现并有上线记录；本轮未重新检查线上服务。上述功能不属于本版新增范围。

现有牌桌采用“选牌，再点打出”，已有立直选择、多方案鸣牌确认、倒计时、合法 optionId、动作回执与重连处理。本版四种入口必须统一进入同一动作提交与幂等流程，不能各自建立一套出牌逻辑。

## 3. 快速出牌

### 3.1 普通模式与快速模式

普通模式保持“选择一张合法牌 → 点击打出”。快速模式开启后，在本人可操作的普通弃牌阶段，单击鼠标或单次轻触某张合法牌，直接提交该实体牌对应的 `DISCARD`，不要求二次点击“打出”。

开启快速模式本身不提交已经选中的牌；切换模式清除原选牌。模式名称旁持续显示“单击即出牌”，首次开启展示一次可关闭的说明，不在每次出牌时弹窗。

快速模式不采用双击手势，不使用右键出牌，不改变牌序，不提前选定下一巡要出的牌。非本人行动、非法牌、托管中或待确认回执时，点击不得生成动作。

### 3.2 立直及特殊操作

点击“立直”或按 R 只进入立直选牌状态，不出牌、不扣立直棒。此状态即使开启快速模式，点击合法牌也只选中；必须再点“立直并打出”或使用键盘确认，提交一个 `RIICHI_DISCARD`。

取消立直选择不视为过牌。立直成立后，普通快速出牌只允许服务端当前合法的摸切牌；不能通过同种牌、排序位置或旧选择换打手里的另一张实体牌。

吃、碰、杠、九种九牌、自摸与荣和沿用各自入口及确认流程，不由点击手牌推断。吃碰后的弃牌可使用快速模式，但仍严格遵守合法选项与食替限制。

### 3.3 指针与触控保护

只在主指针的一次有效点击完成后处理，不在 pointerdown／touchstart 时出牌。按下与抬起必须属于同一张实体牌、同一决策；移动超过 8 CSS 像素、多点触控、滚动、指针取消、抬起到另一张牌或覆盖层出现，均取消这次快速出牌。

手势按下后若发生换窗、失去焦点、快照改变可操作资格或实体牌已失效，抬起不得出牌。触控生成的兼容鼠标事件、双击第二次事件和组件重渲染不能重复提交。

已经提交到服务器的出牌不能撤销；快速模式不会提供假撤回。界面说明应在开启时明确这一点。

## 4. 自动摸切

### 4.1 含义与触发条件

牌桌提供独立“自动摸切”开关，开启后显示持续高亮及说明：“自动打出新摸到的牌；和牌、杠等选择会暂停本次自动操作。”

仅当以下条件全部满足时，才可为当前决策安排自动动作：

1. 比赛处于运行中，本人是当前摸牌后行动者，存在服务端给出的 HUMAN 决策且 `canSubmit=true`。
2. 当前登录、控制 binding 与最新已安装快照一致；连接可用，页面可见且窗口有焦点，没有待处理／结果不确定的动作。
3. `self.drawnTile` 不为 null，且存在 `type=DISCARD`、`tile=self.drawnTile` 的当前合法选项。
4. 当前决策没有自摸、暗杠、加杠或九种九牌选项；没有立直选牌、操作弹窗或本次手动介入标记。

只使用精确实体 ID，不能把普通五与赤五、手中旧牌与本次摸牌互换。一般摸牌与岭上摸牌遵守相同条件。

开启时若当前决策已经符合条件，可以安排本次摸切；开关必须说明会立即对本次行动生效，并先经过下述取消等待。不开启时，即使已经立直，也不会新增客户端自动摸切；原服务器超时策略仍保留。

### 4.2 特殊选择与手动介入

| 当前情况 | 自动摸切行为 |
| --- | --- |
| 正常摸牌，有合法摸切、无需手动确认的特殊选项 | 等待后自动提交该摸牌的 DISCARD |
| 同时可立直，但玩家尚未进入立直选牌 | 仍可普通摸切，不自动立直；开启说明明确可能放弃本次立直机会 |
| 可自摸 | 暂停本次决策，显示自摸及手动操作，不放弃和牌 |
| 可暗杠／加杠／九种九牌 | 暂停本次决策，交由玩家明确选择 |
| 吃碰后弃牌，没有本次摸牌 | 不自动挑一张手牌，必须手动弃牌 |
| drawnTile 不合法或没有匹配 DISCARD | 不尝试替代牌，等待权威状态或手动操作 |
| 当前决策由 AI 处理／正在恢复人工 | 不生成动作，不能抢走 AI 当前窗口 |

特殊选项导致暂停时，仅暂停当前决策；玩家手动完成后，下一次符合条件的摸牌可继续自动摸切，不要求每巡重新开启。它不自动选择“不杠”或“放弃自摸”，也不因暂停延长截止时间。

玩家选择手牌、进入立直、打开当前行动选项、按“本次手动”或开始合法手动操作时，立即取消尚未发送的自动动作，并将当前决策标为手动处理；同一决策不能因重新渲染又自动安排。选择手牌本身不关闭整场开关。

### 4.3 取消等待

自动摸切从条件首次满足起等待 500 毫秒，显示“即将自动摸切”和“本次手动”按钮。在发送前，每次条件变化和等待结束都重新校验完整决策、模式与控制权。

关闭开关或按“本次手动”可取消尚未发送的动作。若已发送，明确显示“已提交，等待确认”，不能承诺取消已提交动作。

若客户端估算距离截止不足或等于 500 毫秒，本次不安排自动摸切，不通过缩短等待或补发旧动作抢截止；提示由玩家手动处理，最终以服务器时限裁决。延迟回调不能把过期动作发到下一窗口。

截止估算使用服务端时间与浏览器单调计时，不因本机系统时间调整重置等待或延长窗口。每个决策最多安排一次有效的自动发送；明确拒绝后不循环重试，先同步并交给玩家处理。

## 5. 不鸣牌

### 5.1 固定含义

牌桌提供独立“不鸣牌”开关，副文案为“不吃、不碰、不明杠；仍提示荣和”。开启不表示屏蔽所有响应，也不表示自动和牌。

- 只针对他家弃牌响应中的 `CHI`、`PON`、`DAIMINKAN`。
- 本人行动中的 `ANKAN`、`KAKAN` 不属于此开关控制范围。
- 荣和及抢杠荣和始终保留。不能自动 PASS 含合法 `RON` 的决策，否则可能产生振听。
- 不修改服务器返回的合法选项，也不告诉其他玩家本人是否打开开关。

### 5.2 响应规则

| 当前合法选项 | 不鸣牌开启时的行为 |
| --- | --- |
| PASS 与吃／碰／明杠，无 RON | 500 毫秒取消等待后自动提交原 PASS optionId |
| RON、PASS，可能同时有吃／碰／明杠 | 不自动提交；保留荣和／过牌，吃碰明杠入口禁用并说明需先关闭不鸣牌 |
| 抢杠响应含 RON | 保留荣和／过牌，不自动选择 |
| 仅有 PASS 的有效可提交决策 | 可按同样等待提交 PASS；若服务端没有为此座位建立决策，则什么也不发送 |
| 没有有效 PASS、已提交、AI 决策或没有操作权 | 不生成动作 |

此处取消等待、临近截止与手动介入遵守自动摸切的 500 毫秒规则。开启不鸣牌可以影响当前尚未提交的响应；关闭后恢复当前仍有效的鸣牌入口，不撤回已经提交的 PASS。

自动 PASS 成功只表示响应已收录，不表示他人的碰已成立或本窗口已经结束。仍由服务器收集全桌响应、处理荣和优先、双响与三家和等规则。

若玩家明确选择放弃合法荣和，提交 PASS 前展示确认，说明可能产生同巡振听或立直后振听；默认焦点在取消。确认后使用原 PASS，振听由服务器按规则计算。不鸣牌不会自动触发这一确认或替玩家确认。

## 6. 键盘操作

### 6.1 启用与作用区域

默认关闭。设置提供“启用键盘操作”，牌桌提供“聚焦牌桌”入口。快捷键仅在运行中牌桌的操作区域或其专用选项弹窗拥有焦点时生效，焦点位置清楚可见。

以下情况不执行牌桌快捷键：输入框、文本域、下拉框、contenteditable、输入法组合输入、按住 Ctrl／Command／Alt、浏览器失焦、页面后台、账号／好友／规则／设置等覆盖面板打开、回放／结果页、没有控制权或正在等待回执。

不劫持浏览器刷新、返回、复制、缩放或操作系统快捷键。未启用时保持原生按钮的 Tab／Enter／Space 行为；启用后也不能破坏原生按钮操作。屏幕键盘按键和读屏激活不等同于鼠标快速点击。

### 6.2 固定映射

字母使用 `KeyboardEvent.key` 的大小写不敏感值；不支持自定义键位或宏。按键行为以当前权威合法选项为准，不根据客户端自行推算役种或鸣牌资格。

| 按键 | 功能 |
| --- | --- |
| ←／→ | 在当前可选手牌中移动选择；循环遍历，同种牌仍按实体逐张定位 |
| Home／End | 选择最左／最右的合法手牌；独立摸牌按其当前屏幕位置参加遍历 |
| Enter | 有已选合法手牌时确认普通弃牌／立直弃牌；无选择时不自动选择摸牌 |
| R | 有合法立直选项时进入／取消立直选牌；不直接提交立直 |
| C | 打开合法吃牌方案选择；不直接吃牌 |
| P | 打开合法碰牌方案选择；不直接碰牌 |
| K | 打开当前合法杠方案；暗杠／加杠／明杠按牌形与类型分别列出 |
| W | 打开合法自摸／荣和确认；不存在和牌选项时不动作 |
| Space | 有合法 PASS 时请求过牌；若同时可荣和，先显示放弃荣和确认 |
| Escape | 关闭当前行动选择／确认；无弹窗时先取消立直选择，再清除手牌选择；不提交 PASS |
| Tab／Shift+Tab | 保留原生焦点移动，不作为出牌或选择策略 |

快速出牌只改变指针点击行为。键盘始终“选择 → Enter 确认”，即使快速模式已开，也不能因方向键移动就出牌。第一次方向键操作在未选择时定位首个／末个合法候选，不推断最佳牌。

不提供快速切换自动摸切／不鸣牌的单字母快捷键，避免输入或误触开启自动动作；可通过 Tab 聚焦相应开关并用原生操作启停。

### 6.3 选项弹窗与重复按键

吃、碰、杠即使只有一个合法方案，也先展示对应方案和消耗实体牌，再由一次新的 Enter 确认；多方案使用方向键移动，Enter 确认。保留响应来源、目标牌、赤五、消耗手牌与倒计时。弹窗内不得触发背景牌桌按键。

W 打开的和牌确认显示自摸或荣和及来源，使用新的 Enter 确认；不能用 Enter 在没有明确选择时优先和牌。Escape 取消确认不等于过牌，不产生振听。

忽略 `event.repeat`，同一按键必须释放后才可在下个决策／新弹窗再次生效；长按 Enter、Space、字母或方向键不能连续出牌，也不能在一次按压中打开并确认弹窗。

快捷键处理和按钮原生 click 必须只走一次激活路径，防止 Enter 同时触发全局处理和按钮 click。焦点已在原生按钮时优先由该按钮的原生语义处理，不能叠加背景快捷键；快速模式中的牌按钮经键盘激活仅选牌，不直接快速出牌。确认按钮必须标注用途。

## 7. 四种操作的优先级与统一调度

### 7.1 每个动作必须满足的条件

普通点击、快速点击、键盘确认、自动摸切和自动 PASS 均通过同一提交入口。提交前以最新状态核对：

- 本人会话、身份代际、连接、binding 和 HUMAN 操作资格有效。
- `matchId + handId + serverEpoch + windowId + decisionId` 与当前快照一致。
- 选项仍存在，optionId 和实体牌仍对应原选择，未超时、未提交、无结果不确定的在途请求。
- 模态界面、自动开关、当前焦点及手动介入状态允许本次动作。

生成一次 requestId 后冻结该逻辑动作，以同步互斥标记先占用提交权，再更新界面和发送；不能仅依赖 React 异步 pending 状态阻止同一帧的双事件。自动定时器、手动操作和重复快照共用这个锁。

### 7.2 优先级

1. 会话失效、断线、失去操作权、决策变化或关闭自动模式：取消尚未发送的自动任务。
2. 未发送前的明确手动介入：取消当前自动任务，本次决策交给手动处理。
3. 自摸／荣和等需要玩家决定的选项：自动模式让出，不自动放弃。
4. 当前仍符合条件时，自动摸切或自动 PASS 才能提交。

若定时器已先占用提交权并发送，随后到来的手动操作只提示等待，不再提交另一个选择。开关和取消按钮仍可关闭后续自动任务，但不能撤回在途动作。

自动摸切和不鸣牌可以同时开启，分别处理摸牌行动与他家响应，不为同一决策安排两个动作。快速出牌和键盘控制可同时开启，均不能绕过上述优先级。

### 7.3 快照与回执

收到更高 viewSeq 的完整快照本身，不等于出现了新的决策。如果决策标识、选项、资格均未改变，不清除已经占用的动作锁、不重新安排等待、不重发动作，也不随意清除玩家当前合法选牌。

当决策、handId、serverEpoch、身份／binding 或可操作资格改变时，取消旧计时器，清理失效选择、立直和弹窗。来自旧身份、旧窗口的异步回调不能更新当前牌桌。

提交后显示“已提交，等待裁决”。回执丢失时查询既有请求回执并同步快照；查询 404 仅表示尚未查到记录，不能据此生成新 requestId 或改选另一张牌。

需要重试时，沿用原 requestId 和相同逻辑载荷，并遵守既有 binding／同步规则；原动作跨窗口或不再获授权时不得强行重发。服务端按原协议去重、检查入队时刻和截止，不因快速操作给予额外时间。

出现提交结果不确定或恢复失败时关闭两个自动开关，当前相关决策保持恢复中，直到权威回执或状态明确。不能立即解锁并自动提交第二个选择。自动动作与服务器超时／AI 动作竞争，只允许一个有效结果，拒绝不作为客户端自行推进牌局的依据。

## 8. 生命周期与设置保存

### 8.1 偏好与运行开关

| 项目 | 保存策略 |
| --- | --- |
| 快速出牌偏好 | 当前浏览器内按环境和 userId 保存；不跨账号共用，不承诺跨设备同步 |
| 键盘操作偏好 | 同上；重新进页仍须聚焦牌桌才激活快捷键 |
| 自动摸切 | 仅当前页面、当前 matchId 运行开关，不写入持久浏览器偏好或账号资料 |
| 不鸣牌 | 同上；不在新比赛、刷新或恢复连接后自动打开 |
| 当前选牌／立直／弹窗 | 仅当前有效决策，不能带入下一窗口 |
| 在途动作 | 沿用受身份／比赛约束的请求恢复记录；不是自动模式偏好 |

快速和键盘偏好解析失败、存储不可用或用户首次使用时均回落关闭，不阻止出牌；页面可以显示设置无法保存。不得为四项能力创建账号云端设置表。

### 8.2 重置条件

两个自动开关在同一场比赛的正常局间结算中可以保留，下一局仍重新按条件判断并等待 500 毫秒。比赛最终结束、技术中止、同桌再战产生新 matchId、离开牌桌、页面刷新／关闭、退出或切换账号时全部关闭。

断线、窗口失焦、页面隐藏、系统锁屏导致页面失活、打开遮挡牌桌的账号／好友／规则／设置面板、控制权被接管、转 AI／等待恢复人工、会话被远端撤销，以及 serverEpoch 改变时，取消自动任务并关闭两个自动开关。回到前台或恢复连接后显示简短提示，需要本人重新开启；不补做后台期间的自动动作。

恢复前台必须安装有效权威状态后才允许重新开启，不能直接根据旧缓存发送。服务器 AI 托管继续遵守原规则；关闭客户端自动操作不停止服务器计时或托管。

快速／键盘偏好可以保留，但失效期间不可操作，所有手牌选择和按键按下状态必须清除。接管到新设备时不继承另一设备的自动开关。

## 9. 界面与无障碍要求

牌桌操作区提供快速出牌、自动摸切、不鸣牌、键盘四个带文字的开关；在窄屏可折行，不横向挤压手牌或遮挡动作按钮。自动模式提供持续状态条、待发送说明、单独关闭及“停止自动操作”入口。

不同状态必须可区分：关闭、开启等待、当前需手动、已提交待确认、无操作权。开关使用文字与可访问状态共同表达，不能只靠颜色。两个自动开关无操作权时仅允许关闭，不允许开启。

快速模式下不会再提示“先选牌再打出”；立直、键盘及特殊暂停时使用对应说明。保留最新弃牌、响应来源、倒计时、赤五标记和实际消耗牌显示。

手牌和选项显示清楚的键盘焦点与选中状态，两者不能混淆；Tab 顺序可预测，弹窗关闭后焦点回到合理入口。使用读屏可读的牌名、开关名称与确认按钮名称；自动状态变化使用适度的状态提示，不每秒播报倒计时。

移动端不依赖悬停或物理键盘；所有键盘能力仍有触控按钮。滚动、旋转、布局尺寸切换、减少动画和正常重渲染不能产生隐式出牌或延长时限。

## 10. 技术与协议工作范围

本版计划以客户端增量实现，不新增 HTTP 写接口、账号设置表、数据库迁移、房间规则字段或服务器自动操作定时器。`APP_VERSION` 与打包版本在实施时一致升至 `0.4.2`，本文创建不修改版本。

使用现有 `game:action`、`game:sync`、动作回执查询和控制机制。自动摸切发送 DISCARD，不鸣牌发送 PASS；不新增 AUTO_DISCARD／NO_CALL 等麻将动作，也不把偏好写入牌谱冒充规则。

牌谱照常记录最终动作及摸切事实；不承诺区分点击、键盘、自动摸切或服务器默认行为的额外分析数据。若诊断增加入口类型，只能是白名单枚举，不记录原始键盘输入、口令、会话秘密或不可见牌。

实现应将“输入意图、候选自动动作判断、取消与提交互斥”从现有牌桌渲染中提取为可验证的逻辑，统一复用动作通道。现有每次 viewSeq 都重置交互状态、失败后解锁及在途恢复处理，须按本文件逐项检查，不可直接将自动定时器附加到渲染循环。

规则引擎、服务器裁决和隐私投影保持权威。若回归暴露已有动作恢复缺陷，应做最小修复并单独记录；若确需新增服务端契约、迁移或修改规则，先修订受影响文档，不默默扩大本版范围。
