## 1. 次版目标与现有基础

首版已具备好友组局、四人东风战、AI 补位、服务器裁决、重连托管、结算和牌谱回放等核心功能。次版目标是让玩家可以**选择更完整的赛制、连续和朋友玩、找回历史比赛，并获得更顺畅的手机与复盘体验**。

本范围以用户确认的“首版功能已实现”为前提，并核对了当前仓库，不重新把已有核心能力包装成新增需求。

- **P0：V2 必做。** 全部完成且通过验收才可宣称本范围交付。

### 2.1 玩法与模式的界限

“AI 练习”指开场时一名真人加三名 AI；“多人好友场”指开场时至少两名真人。模式依据开场配置固定，不能因中途掉线托管重新分类。

两种模式的麻将规则相同。比赛结果继续记录最终点数、净得失与名次，不增加段位分、马点或头名赏。

半庄使用既定规则中东一至南四的计划赛程；必要时延长至西场，最多到西四的硬上限。东风战的南场是延长场，半庄的南场是计划场，必须在数据和画面中区分。

## 4. 主要页面与流程

### 4.1 首页与准备厅

首页增加“历史战绩”和“我的统计”。存在进行中比赛时继续显示恢复入口，不允许借新入口同时进入另一场比赛。

创建房间时选择东风／半庄；进入等待房间后，只有房主可以改赛制与机器人难度。非房主必须能看见当前赛制和 AI 难度。

任何影响下一场配置的变更都会清除全部真人准备，并明确提示“配置已变更，请重新准备”。双方同时修改或开始时，由服务器版本校验决定，不按客户端显示顺序推断生效值。

开场确认区显示赛制、时限、机器人难度和固定规则摘要。半庄不承诺固定时长，不能标注“必定八局结束”。

### 4.2 半庄完整流程

除赛程外，半庄沿用原有和牌、支付、连庄、振听及信息隔离逻辑。25,000 起点与 30,000 终局目标不变。

必须单独覆盖：

- 东四换庄后进入南一，不套用东风战结束条件。
- 南四庄家和了止／听牌止，以及庄家未满足条件时继续连庄。
- 南四应换庄、无人达到目标时进入西一。
- 西场达到目标即终局，以及西四硬上限。
- 任何场次的飞人优先级、最终供托一次清算、同点排名。
- 半庄期间掉线、进程恢复和回放时保持原赛制。

画面中的“南场”不能自动标为“延长”；isExtension 必须由赛制和实际进度计算。把现有 EAST_ONLY 字面量替换成枚举并不等于完成半庄。

### 4.3 同桌再战

一场正常结束、最终结算提交后，房主可选择“同桌再战”，使房间由 FINISHED 回到 WAITING。服务器原子创建新的准备轮次编号，保持原 roomId 与邀请码，暂不创建下一 matchId。准备阶段房间的当前 matchId 置 null，上一场通过独立历史引用保留，不能把旧 matchId 当作下一场活动比赛。

下一场必须满足：保留的四个位置有成员、至少一名真人、所有真人重新准备、房主再次点击开始。不能因为上一场曾准备就自动开场。

| 对象 | 再战时处理 |
| --- | --- |
| 原比赛 | matchId、结果、牌谱和成员快照保持只读 |
| 房间配置 | 默认沿用，可由房主在等待阶段修改 |
| 真人成员 | 保留在等待房间，准备全部归零；主动离开可释放位置 |
| 机器人 | 保留等级配置；房主可增删 |
| 新比赛 | 开始时分配新 matchId，重新随机初始座位，四家点数重置为 25,000 |
| 牌局状态 | 不带入旧手牌、立直、振听、本场、供托、控制窗口或操作编号 |

离线真人只在**上一场已正常结束并进入再战准备厅后**适用清位：进入时已离线者从进入时开始计 30 秒，之后才离线者从实际离线时开始计 30 秒，仍离线则退出等待位置；期间恢复在线则取消清位，之后再次离线重新计时。正常在线但未准备者不自动移除。新建首场房间的断线行为继续沿用首版，不默认启用此再战清位规则。

原房主离开或被上述规则清出时，转交给加入最早的剩余真人；没有真人则关闭房间。该清位规则不适用于进行中的比赛，也不改变掉线玩家已结束场次的成员身份和成绩。

再战请求需要幂等键及准备轮次校验。旧轮次延迟到达的准备、配置、离房和开场请求不能修改新轮次。进行中比赛不能通过再战强制结束；技术中止场本次仍采用明确退出、创建新房间的路径。

新加入同房间的人，只能读取自己实际参加的比赛。房间成员身份不能授予此前所有比赛的牌谱权限。

### 4.4 历史战绩与比赛详情

历史入口按当前游客 userId 查询，不从浏览器缓存猜测全量历史。有效比赛按结束时间倒序排列，每页 20 场，使用稳定游标；相同结束时间再以 matchId 稳定排序。

支持筛选赛制（全部／东风／半庄）与模式（全部／AI 练习／多人好友场）。技术中止单独标签展示，不混入有效比赛统计；当前进行中的比赛仍通过“继续对局”入口访问。

每项显示时间、赛制、模式、本人名次／最终点数／净得失、对手及 AI 难度摘要，并进入只读比赛详情。详情显示四家成绩、逐局结果与对应回放入口。

列表与详情只返回摘要，不下载全部牌谱或全量隐藏状态。只有用户进入有权查看的已结束牌谱时，才加载所需回放数据。

牌谱已超过保存期时，显示“牌谱已过保存期”，不能保留失效按钮。若成绩摘要仍保留，保留它不代表完整牌谱也仍存在；保留期限以明确的服务配置和玩家说明为准。

### 4.5 统计口径

统计默认显示最近 30 天，并可按东风／半庄、AI 练习／多人好友场筛选，不默认混合不同模式比较。

| 指标 | 定义 |
| --- | --- |
| 有效场数 N | 指定时间范围和筛选条件内，参与且正常 FINISHED 的比赛数 |
| 一位率 | 本人最终名次为 1 的有效场数 ÷ N |
| 平均顺位 | 本人最终名次之和 ÷ N |
| 名次分布 | 第一／第二／第三／第四各自场数与占比 |
| 平均净得失 | 各场本人“最终点数减 25,000”之和 ÷ N |

N=0 时，场数显示 0，比例与平均数显示“暂无数据”，不用 0% 或平均第零名误导。飞人正常终局计入；技术中止、尚未完成及内部模拟不计入。

同点名次使用原比赛已保存的结算结果，不按今日成员顺序重新排名。托管结束的有效场仍属于原玩家；不能通过离开或掉线隐藏不利成绩。

统计显示统计区间和样本数；同一比赛重发或恢复不重复计数。次版不展示荣和率、放铳率等需要另定局级口径的指标，也不把这些统计换算为段位。

### 4.6 BASIC 与 STANDARD AI

| 等级 | 定位 | 必需差异 |
| --- | --- | --- |
| BASIC | 适合熟悉操作与基础做牌 | 基础向听／进张、做役、合法和牌；采用较简单的立直和防守权重 |
| STANDARD | 常规好友房与较完整的基础对手 | 保留现有向听／进张、做役、立直、现物防守；加入赛制、场风、名次和终局阶段的一致判断 |

不是仅增加随机失误概率或把 BASIC 变成纯随机出牌。两档始终遵守完整规则，并使用相同受限视图、合法动作和超时兜底。

半庄接入后，AI 不能再把所有“第四局”都当作最后阶段；也不能只按东风的延长标记判断局况。难度在开场前确定，对局中不自适应升降。

机器人保存 botLevel 与 botPolicyVersion；回放读取实际记录动作，不重新运行新策略。真人掉线托管默认使用 STANDARD，不能读取比原座位更多的信息。

固定场景需证明两档在预定攻守或立直取舍上有可解释差异；批量对局用于检查稳定性与趋势，不保证 STANDARD 每一场获胜，也不承诺达到某个网络平台段位。

### 4.7 回放增量

保留原有选局、步进、播放／暂停、座位／全信息视角和 JSON 导出，增加：

- 关键事件列表：立直声明／成立、成功鸣牌、候选杠／抢杠、和牌与流局。
- 点击事件定位到明确的事件序号与对应局面，候选杠不能误画成已成功杠。
- 本人上次观看的位置、查看座位与公开视角状态；默认不恢复全信息展示，重新进入时全信息开关关闭。
- 从历史比赛的某一局结果直接进入对应回放位置。

观看位置按 userId＋matchId 保存，供同一有效身份刷新后恢复。位置越界、旧牌谱缺少事件索引时安全回到局首，并提示原因，不改写牌谱内容。

本次不加入外部牌谱导入、公开分享或 AI 评分。旧牌谱没有新字段时，先适配原版本，不能要求历史比赛重新生成。

### 4.8 手机与操作体验

保留默认“选牌再确认”以控制误触。V2 增加紧凑／标准牌桌尺寸、减少动画设置，并修正切换窗口、收到新快照、进入托管后的残留选中状态。

已有最新弃牌和响应来源提示需在小屏实机检验，强调来源座位、目标牌、赤五区别及实际消耗牌。倒计时和合法按钮不因提示层或动画遮挡。

设置在当前浏览器保存，不承诺账号跨端同步。切换布局与横竖屏不会重新发出动作、重开窗口或延长时限。

本次不默认引入单击直接出牌、拖拽理牌或自动和牌。新增动画须能跳过；普通网络重连仍不加时。

### 4.9 问题定位入口

设置／错误提示中提供“复制诊断信息”，输出诊断编号、程序版本、协议／规则版本、roomId／matchId／handId、当前阶段及可见状态序号等必要信息。

不复制 Cookie、会话密钥、bindingId、原始请求认证信息、暗手、未来牌山或完整私有响应。复制内容由白名单生成，不能直接导出整个 MatchState。

复制不会自动向任何外部平台发送消息。服务端日志能据诊断编号定位同一时段的已提交操作、恢复或中止事件；普通玩家只看到可理解的状态与编号。

## 6. 首版继承质量门槛

## 7. 数据与权限边界

### 7.1 新增或扩展的数据

| 数据 | 最低内容 |
| --- | --- |
| 房间准备轮次 | roomId、lobbyGeneration、当前配置、ready 状态、离线清位截止、当前 matchId 与历史 match 引用 |
| 比赛成员快照 | matchId、userId／机器人标识、固定初始 seat、开场昵称、开场模式、AI 难度与策略版本 |
| 历史摘要 | matchId、开始／结束时间、赛制、模式、状态、四家最终成绩、规则／协议／牌谱版本、回放可用性 |
| 本人查询索引 | userId＋结束时间＋matchId，以及赛制／模式筛选所需字段 |
| 统计 | 来源比赛可追溯、时间范围与筛选条件；若使用缓存须有失效／重建方式 |
| 回放观看位置 | userId、matchId、handId、稳定事件序号、查看 seat、更新时间 |

新成员不能凭同一个 roomId 获取旧比赛内容。历史查询、统计、回放和观看位置都以经过认证的 userId 为权限边界，不接受客户端自报 userId 作为授权。

### 7.2 保留与旧数据补全

延续正常成绩和完整牌谱至少 30 天、回执至少七天的既有承诺；进行中数据不按结束后期限清理。新增统计只能基于仍保留且可核对的有效摘要，页面说明区间，不把有限保存数据宣传为终身战绩。

旧首版比赛可根据其明确来源补全 format=EAST_ONLY；AI 难度只有在能够确认原实现策略时标记为旧版 STANDARD，并保留 legacy 来源说明。未知版本、缺少成员或点数不守恒的记录进入异常清单，不猜测补成有效成绩。

摘要索引可重复构建，并以 matchId 唯一约束防止重复记录。禁止为新增统计覆盖原始 finalPoints、名次或终局原因。正常中止记录也不能被“回填”成 FINISHED。

## 8. 协议与接口工作范围

本节列出待实施的契约工作，不表示相关接口已经存在。正式编码前形成《对局状态与通信协议 v2.0》，并与 Schema、共享类型一起评审。

| 方向 | 待新增／修改的能力 |
| --- | --- |
| 配置 | Room／MatchView 支持 EAST_ONLY、HANCHAN；botLevel 支持 BASIC、STANDARD；保存 botPolicyVersion |
| 房间生命周期 | 增加 lobbyGeneration，所有准备／配置／开始／离房操作检查轮次；正常结束后受控回到 WAITING |
| 能力协商 | 客户端读取实际开放赛制、AI 等级与协议能力，不依靠硬编码空入口 |
| 历史列表 | 本人分页查询摘要，稳定游标、赛制／模式筛选，响应中无完整隐藏状态 |
| 比赛详情 | 本人已参与比赛的只读结果与逐局摘要、回放可用状态 |
| 统计 | 按本文固定口径查询本人区间统计，无需下载全部完整牌谱 |
| 回放位置 | 本人观看位置读取／保存，校验有权限且事件定位有效 |
| 诊断 | 获取／复制诊断编号及白名单上下文，不提供暗手与凭据导出 |

多人响应收录、合法 optionId、持久化回执、单一控制连接、个人完整快照与事件可见性继续沿用现有一致性原则，不因新列表或新房间流程退化。

新增查询不得在主事件循环中每次反序列化全部比赛与牌谱。历史查询应使用摘要与可分页索引，避免本地有少量数据时正常、上线积累后阻塞对局。

旧房间状态机及封闭枚举与再战／新难度存在不兼容风险，因此本范围按协议 2.0 规划；发布前冻结最终契约。若实施时选择兼容小版本，必须有旧客户端兼容证据，不能只修改版本字符串。

## 9. 发布、迁移与回滚

1. **固定基线**：保存当前可运行发行版本、规则／协议与验收报告；不把正在变化的工作区当作可回滚包。
2. **新增结构**：迁移历史摘要、索引、准备轮次与版本字段；优先采用可向后读取的新增字段，不破坏原比赛与牌谱。
3. **离线回填**：在备份副本验证旧记录回填与统计，确认唯一性、权限及点数；输出异常清单。
4. **升级演练**：覆盖有效旧战绩、旧回放、待开房间与再战后的恢复；迁移重跑不重复记录。
5. **部署切换**：本次默认维护发布。先停止新开场，等待已有进行中比赛正常结束；不得为升级直接判中止、重置点数或强行切换赛制。未结束则延后切换。
6. **客户端更新**：不兼容旧客户端应明确提示刷新；保存的旧牌谱使用原解码适配，不能因客户端升级拒绝全部旧记录。
7. **回滚约束**：旧程序若不能解释新增半庄／再战数据，不能直接指向升级后的库。须保留可读新数据的修复版本，或在确认无新增对局写入时恢复发布前快照；不能回滚后抹掉用户新成绩。

此处只要求制定并验证发布方案，不授权本次文档生成直接变更生产服务、DNS 或数据库。

## 10. 性能与可用性目标

继续沿用首版记录环境后的 10 桌目标，同时加入战绩与回放查询负载：

| 指标 | 验收目标 |
| --- | --- |
| 有效动作接受回执 | RTT 不高于 100ms 的同一测试基线中，端到端 P95 ≤300ms |
| 收齐／截止后的裁决推送 | 服务端处理 P95 ≤300ms，不把规定响应等待计作处理慢 |
| 正常 AI 决策 | 两档分别报告，目标 P95 ≤500ms，不阻塞其他房间 |
| 完整快照恢复 | 认证及连接恢复后 P95 ≤3 秒，控制权仍按窗口边界处理 |
| 历史摘要分页 | 以 10,000 场合成摘要为查询基线，每页 20 场，服务端 P95 ≤500ms |
| 并发查询影响 | 对局压测同时执行每秒五次摘要查询、每秒一次回放打开，不突破上述对局时延目标 |

合成数据只进入隔离测试库，不混入实际战绩。查询基线不等于承诺存储所有玩家无限历史，也不等于承诺新增并发桌数。

手机延续 640×360 CSS 像素横屏牌桌、360 像素宽竖屏入房基线。新战绩表与回放导航必须实际触控验收，不能仅用桌面缩窄窗口确认完成。
