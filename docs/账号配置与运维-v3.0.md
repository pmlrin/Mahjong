# 账号配置与运维 v3.0

适用程序 0.3.0。真实邮件注册、登录、找回及旧会话撤销已在预览验证。2026-11-01 用户确认手机页面正常后要求正式上线，正式根站已切换到 V3；101 项回归通过，具体设备分项与继承质量待项继续跟踪。正式配置与迁移证据见 [第三版正式上线记录](第三版正式上线记录-v3.0.md)。

## 环境与配置

Node.js 最低 24.7，实际验证为 24.22.1。密码使用 Node 原生异步 Argon2id，参数为内存 19,456 KiB、2 次、并行度 1；进程最多同时执行 2 个任务，最多排队 32 个。参数参考 [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，API 参考 [Node crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html)。本机计时不代替生产负载验收。

本地运行 `pnpm auth:configure` 会先验证目标文件被 Git 忽略，再以 0600 创建 `.env.auth.local`；已有文件拒绝覆盖。生成独立 OTP HMAC 秘密和 AES-GCM 密钥，SMTP 密码保持空白。请在本地编辑器填写，勿贴到聊天。邮箱白名单实际地址也只放受限配置。

配置后可用 `node --env-file=.env.auth.local --import tsx backend/src/server.ts` 启动。普通 `pnpm start` 不自动加载此文件。没有邮件配置时不会发送邮件、不会回显验证码，游客和已有账号密码登录继续工作。

服务器发行包包含 `.env.auth.example` 和编译后的工具。在新发行目录执行：

```sh
# 使用现有预览环境的 SESSION_SECRET，避免无意更换已有幂等上下文密钥。
/opt/mahjong/runtime/bin/node --env-file=/opt/mahjong/v2-preview.env \
  backend/src/auth/configure.js /opt/mahjong/v3-preview-auth.env --server
```

该工具拒绝覆盖旧文件，`--server` 目标须为 `/opt/mahjong/` 下的新 `.env` 文件。生产配置加 `--production`。不要将预览配置复制为正式配置；独立生成各环境 OTP/AES 秘密。若不从已有环境加载 SESSION_SECRET，工具会生成新值，已有站点更新时应继续使用既有值。

由服务账号读取配置，0600；共享预算目录应归同一麻将服务账号所有，权限 0700。主服务环境文件仍提供 DATABASE_URL、SESSION_SECRET、PUBLIC_ORIGIN；账号文件作为附加 EnvironmentFile 加载。正式 Cookie 为 `mj_session`、路径 `/`；预览为 `mj_preview_session`、路径 `/preview`。生产必须 HTTPS；PUBLIC_ORIGIN 填主机来源，例如 `https://mahjong.yangjm.cn`，不含 `/preview` 路径。

| 配置 | 要求 |
| --- | --- |
| AUTH_ENABLED | true/1 开放新账号入口；false 不会把已有账号变为游客，仍可密码登录 |
| EMAIL_VERIFICATION_ENABLED | true/1 且其余配置齐全才开放注册与找回 |
| MAIL_ENVIRONMENT | preview / production；数据库写入环境标识，误接另一环境拒绝启动 |
| SMTP_HOST / PORT / SECURE | smtpdm.aliyun.com / 465 / true；始终校验证书，不自动降级 |
| SMTP_USER / MAIL_FROM_ADDRESS | noreply@notify.yangjm.cn |
| SMTP_PASSWORD | 发信地址的 SMTP 密码，仅安全填写 |
| MAIL_FROM_NAME | 一桌麻将 |
| MAIL_TEST_ALLOWLIST | 预览必须非空，逗号分隔；仅名单中的实际请求收件地址会投递 |
| OTP_HMAC_SECRET | 各环境独立生成，至少 32 字节随机源，不复用 SESSION_SECRET |
| MAIL_OUTBOX_ENCRYPTION_KEY | 独立 32 字节密钥的 base64，不能复用其他秘密 |
| MAIL_DAILY_ATTEMPT_LIMIT | 本环境滚动 24 小时 SMTP 尝试预算，默认 100，重试也计数 |
| MAIL_SHARED_BUDGET_PATH | 同一发信地址的两个环境必须指向同一共享预算 SQLite 文件；服务器默认 `/opt/mahjong/mail-budget/provider.sqlite` |
| MAIL_PROVIDER_DAILY_ATTEMPT_LIMIT | 同一发信地址跨环境滚动 24 小时预算，默认 100；两个环境采用同一额度 |

共享文件只存发信地址摘要、尝试 ID 和时间，不共享用户资料、挑战或会话。同机双环境才适用此文件方案；若以后扩为多主机，须先替换为统一预算存储，不可各用一份文件。预留预算后发生崩溃可能保守消耗一次额度，宁可少发，不突破上限。

## 迁移、备份与发布

1. 按现有维护流程备份目标环境数据库，记录发行号、源代码指纹和维护状态。先恢复到隔离副本验证；不能让两个麻将进程并行写同一库。
2. 使用目标环境数据库变量运行 `node backend/src/auth/migrate.js`。源码运行用 `pnpm auth:migrate`。工具对旧会话、房间和比赛做前后摘要比较，只输出计数与摘要，不输出凭据。实际迁移由 `migration.ts` 执行，`backend/migrations/003_accounts_v3.sql` 是可审查的建表镜像，不能只执行 SQL 就省略旧用户导入。
3. 迁移保留原 userId、有效游客令牌摘要及有效期、冻结昵称、点数、摘要和观看位置；昵称冲突使用会话优先、同来源较新记录优先并登记问题，不重写比赛。迁移可重复执行。环境标识不一致时停止，不能靠修改标识让预览库冒充正式库。
4. 先保持邮件开关关闭验证游客、已有账号、房间与回放，再加载目标环境配置。独立预览已验证，2026-11-01 按用户要求正式上线至 0.3.0。
5. 配置 SMTP 密码后，先运行 `node --env-file=... backend/src/auth/verify-mail.js`（源码 `pnpm mail:verify`）。它只做 TLS 连接与认证，不发邮件。认证成功不代表 QQ 收件成功。
6. 在预览页面向确认的白名单邮箱申请注册码，检查 QQ 实际收到的主题、用途和验证码，完成注册；再实际走找回密码、旧设备撤销和重新登录。记录脱敏收件地址及状态，不留验证码和密码。
7. 真机、迁移恢复、V2 继承质量项及 T01–T32 均有证据后，再安排正式发布；正式库不导入预览账号。

数据库备份必须包含 `auth_*` 表、旧 documents、历史与 replay_positions。原 `deploy/backup.sh` 默认备份正式 `mahjong`，不能拿它冒充预览备份；预览须指定自己的库名。配置秘密另行受限备份，尤其保留稳定的 SESSION_SECRET 与队列解密密钥。数据库备份不能公开，旧待发送正文仍可能以密文存在。

已完成 SQLite VACUUM 副本恢复和 PostgreSQL 独立库 pg_dump/pg_restore 演练；后者逐表比较 17 张表内容，账号类型和旧游客撤销状态保留。证据见验收记录。它们不等于已恢复生产数据。

注册产生正式账号后，不得直接回退不认识 `auth_*` 的旧程序，也不得恢复旧快照丢弃新账号或新成绩。关闭 AUTH_ENABLED / EMAIL_VERIFICATION_ENABLED 只关闭新注册／找回，不禁用已有账号认证。应优先部署能读新结构的修复版本。迁移前尚未产生新写入时，才可按维护方案恢复完整备份；不要只删新增表。

## 队列与故障检查

任务为 QUEUED / SENDING / ACCEPTED / FAILED / EXPIRED。ACCEPTED 只表示 SMTP 接受。SENDING 租约 60 秒，重启可回收；临时失败退避 5 秒、15 秒，最多三次实际尝试，同码同截止时间；终态、过期、旧挑战失效均清除正文密文。预算不足、永久拒信、认证与配置错误停止该任务，不无限重发。

先查看脱敏日志的 MAIL_* 错误类别和任务状态计数，再查受限配置及阿里云控制台。日志不得开启 SMTP debug，不导出 ciphertext、code_hmac、完成凭据、密码哈希或 Cookie。认证／解密配置错误将本进程邮件能力标为不可用，修复后重启恢复；已有密码登录和麻将仍可用。不要通过关闭 TLS 证书校验“排障”。连接与证书策略参考 [Nodemailer SMTP](https://nodemailer.com/smtp)，端点参考 [阿里云](https://help.aliyun.com/zh/direct-mail/smtp-endpoints)。

对不确定提交结果，服务重新读取数据库中的资料和撤销状态；读取失败则关闭认证，不能沿用旧有效会话。远端改密后控制释放写入失败可由过期检查重试，撤销后的动作立即拒绝。

## 玩家说明

注册当前游客保留原比赛归属；登录已有账号不合并这份游客记录。已丢失的游客 Cookie 不能按昵称找回。账号不是无限期保存牌谱的承诺。退出只退出当前设备；忘记密码撤销全部旧设备，改密仅保留新签发的当前设备会话。进行中的比赛先托管释放控制，再在本机切换身份；从其他设备找回不会删除原座位或撤回已收录动作。
