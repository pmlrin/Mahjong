# 3D 打牌视角：设计方案

日期：2026-11-11
状态：四期均已实现（静态场景、3D 手牌与操作、动画、性能与收尾），见文末实现记录；尚未提交
前置：`docs/Claude 3D打牌视角交接.md`（必须保留的语义）、`DESIGN.md`（靛染设计系统）

## 已确认的决定

| # | 决定 | 内容 |
| --- | --- | --- |
| 1 | 画面风格 | 靛染延伸到 3D：靛蓝牌毡、骨白牌面、杏色竹层与牌背、哑光材质、柔和光照。不追求动漫高饱和或写实反射。 |
| 2 | 本人手牌 | 3D 渲染，交互由透明 DOM 按钮层承接（见「手牌输入」）。 |
| 3 | 设备优先级 | 先做桌面横屏与手机横屏。竖屏使用平面牌桌。 |
| 4 | 平面牌桌 | 保留现有 `TableSurface` 作为回退与可选项；回放暂用平面。 |

“类似雀魂”仅指镜头视角（坐在本家位置、斜俯视整张桌）。不复制其界面、角色、素材或特效。

## 总体架构

```
Game.tsx
├─ <TableView>  ← 新：按偏好与能力选择
│   ├─ <Table3D view>        懒加载；WebGL 画布 + 手牌按钮层
│   └─ <TableSurface view>   现有平面牌桌（回退）
├─ 网页 HUD（现有 React/CSS）
│   ├─ 玩家信息牌 ×4（头像、名字、点数、风位、立直、在线/托管/思考）
│   ├─ 局况（场风、本场、供托、余牌）——3D 中央另有装饰性显示
│   └─ 操作区 action-row、倒计时、自动状态、恢复/同步
└─ 弹窗与结算（现有，不改）
```

原则：

- **3D 层只读 `MatchView`。** 它是 `view → 场景` 的纯函数式渲染加上表现层插值，不持有对局状态，不判断合法性。
- **所有输入仍经现有控制器。** `use-table-actions` / `TableActions` / `TileGesture` 不改语义；3D 层不直接调用 `emit`。
- **文字留在网页层。** 中文字形在 WebGL 中需要大体积 SDF 字体；名字、点数、按钮、提示都用 DOM，借系统字栈。3D 中仅牌面（贴图）和少量装饰字（中央局况，用 Canvas 2D 以系统字体绘成贴图）。
- **随时可回退。** 3D 失败不影响对局可玩。

## 技术栈

| 用途 | 选择 | 说明 |
| --- | --- | --- |
| 渲染 | `three` | |
| React 绑定 | `@react-three/fiber` v9 | 支持 React 19；场景写成组件，`MatchView` 照常传入 |
| 辅助 | `@react-three/drei` | 只按需用：`RoundedBox`（或自写圆角几何）、`ContactShadows`、`PerformanceMonitor` 等 |
| 动画 | 不引入动画库 | 每张牌一个目标变换，`useFrame` 中阻尼逼近 |
| 字体 | 不引入 | 见上 |
| 模型/贴图文件 | 不引入 | 几何体代码生成，牌面运行时由现有 SVG 生成 |

- 版本在安装时由 `pnpm-lock.yaml` 锁定；选择发布满两周以上的版本。
- `Table3D` 以 `React.lazy` + 动态 `import()` 引入，three 相关代码单独成块，只在进入对局且启用 3D 时下载。打包后核对实际体积（预估压缩后约 200KB，以实测为准）。
- 不新增静态素材文件，因而天然兼容子路径部署；若后续加入音效或贴图文件，一律经 Vite 导入或 `import.meta.env.BASE_URL` 拼路径，并在本文件末尾登记来源与许可。

## 场景

### 坐标与尺寸

- 世界单位 1 = 一张牌的宽度。牌：宽 1、高 1.36、厚 0.78，圆角约 0.08。
- 桌面中心为原点，`y` 向上；本家坐在 `+z` 方向。座位按 `(seat - viewerSeat + 4) % 4` 映射为相对位置 0 本家 / 1 下家（右）/ 2 对家 / 3 上家（左），与现有 `TableSurface` 一致。
- 每个相对座位一个旋转后的局部坐标系，牌河、副露、牌山、牌背在局部坐标中排布，同一套布局函数复用四次。

### 牌的构成

- 一张牌 = 牌面层（骨白 `--tile-face`）+ 竹层（杏色 `--tile-side` / `--tile-back`）两段颜色的圆角盒，牌面一侧贴图。
- **牌面贴图集**：启动时把 `Tile.tsx` 的 SVG 内容（34 种 + 3 张赤五）绘制到一张离屏 Canvas 图集，生成一张纹理，每张牌按 UV 取格。颜色从 `tokens.css` 的 CSS 变量读取并转换，保证与平面版一致。
- 牌背：杏色竹层，无花纹或极淡刻纹。
- 性能起点：所有牌共用一份几何体与少量材质；先用普通 Mesh（最多 136 个），实测帧率不足再改 InstancedMesh + 每实例 UV 偏移。

### 桌面元素与数据来源

| 元素 | 数据 | 表现 |
| --- | --- | --- |
| 牌河 | `seats[s].discards` | 每行 6 张，可多于 3 行；立直宣言牌横放；被鸣走的牌只出现在副露里（与实物一致，牌 ID 不重复），若被鸣走的是立直宣言牌则下一张横放；摸切牌面略暗；最新弃牌上方有杏色标记。读屏用的隐藏文字仍逐张列出含「被鸣」的完整牌河 |
| 副露 | `seats[s].melds` | 按 `sourceSeat` 决定横放牌位置；`ANKAN` 两端牌背；`KAKAN` 加牌叠在横牌上；多组从右向左排 |
| 他家暗手 | `seats[s].concealedCount` | 立起的牌背，只按数量渲染，绝不使用任何牌 ID |
| 本家手牌 | `self.concealedTiles` + `self.drawnTile` | 立在镜头前，摸牌与手牌间留间隙 |
| 牌山 | `liveWallRemaining`、`rinshanRemaining` | 四边各两层牌墙；按剩余数量从固定起点消去。**开门位置为装饰性固定规则**（`MatchView` 无骰子信息） |
| 宝牌指示 | `doraIndicators` | 王牌区翻开显示；另在 HUD 局况中保留平面显示，保证可读 |
| 立直棒 | `seats[s].riichi` | 立直家牌河前一根点棒 |
| 中央局况 | 场风、局数、本场、供托、余牌 | Canvas 2D 绘制成贴图的低台面，四家风位朝向各自；可读性以 HUD 为准 |
| 轮到谁 | `activeSeat` + `phase` | 该家桌沿亮起杏色细条 |

## 镜头

- 透视相机，位于本家后上方，看向桌面中心略偏本家处。当前取值：竖直视场 36°；俯角按画布宽高比取 46°（< 1.8）、41°（1.8–2.2）、36°（≥ 2.2，手机横屏），宽矮画布俯角低一些，纵深压缩后镜头能更近、手牌更大；按画布宽高比二分求相机距离，使四角副露与对家手牌落入画面，并为上下信息牌留出边距。
- 按画布宽高比求解相机距离，使整张桌（含四家副露最大占位）在横屏 16:9 到 4:3 之间都能装下；超宽屏两侧留出牌毡。
- 手机横屏（高度 ≤ 600px）：HUD 收紧，镜头适度拉高俯角，手牌放大。
- 竖屏（宽 < 高）：自动使用平面牌桌，并保留现有“转为横屏”提示。
- 第一期不提供用户拖动镜头。

## 手牌输入

3D 手牌只负责画面；输入由一层**透明 DOM 按钮**承接：

1. 保留现有 `<Tile onClick onPointerDown data-hand-tile aria-label aria-pressed disabled>` 按钮，放进一个覆盖在画布上的绝对定位层。
2. 每次布局变化（窗口尺寸、手牌张数、摸牌）时，把每张 3D 手牌的包围盒投影到屏幕，得到矩形，写入对应按钮的 `left/top/width/height`。
3. 按钮外观透明，但保留焦点外圈（近白 `--color-focus-felt`），键盘焦点在 3D 牌上方清晰可见。
4. 3D 牌的抬起、杏色底条、禁用变暗读自同一组 `selected` / `disabled` 状态。

这样点击、拖动出牌手势、键盘、读屏、`authorized` 检查、提交锁全部沿用原路径；`scripts/verify-table-browser.ts` 中 `[data-hand-tile]` 的选择器继续有效（Playwright 视透明元素为可见、可点击）。

## 网页 HUD

- 四家信息牌改为贴在画布边缘的浮层（本家左下、下家右侧、对家顶部、上家左侧），内容与现有 `opponent-info` / `self-info` 相同。位置用固定的屏幕锚点，不跟随 3D 投影，避免抖动。
- 操作区（`action-row`、倒计时、立直/吃碰杠/和/过/打出按钮、自动状态、恢复）位于手牌上方或右侧，DOM 结构和类名尽量不变。
- `LatestDiscard` / `ResponseSource` 等响应提示继续用平面牌图在 HUD 中显示，保证吃碰时能看清来源牌。
- 弹窗打开时，画布与手牌按钮层同样设为 `inert`。

## 动画

- 以牌 ID（0–135）为键。每帧比较新旧 `MatchView` 得出每张牌的目标位置；牌从当前位置阻尼移动到目标位置。
- 计划动画：摸牌进入、打出飞入牌河、鸣牌时弃牌移入副露、加杠叠放、暗杠翻背、立直横放与点棒落下、和牌时手牌推倒。
- 他家暗手没有 ID：只按数量增减，打出的牌从该家手牌位置出现后飞入牌河。
- 断线重连、首次进入、切换局、跳帧（一次更新包含多步）：直接定位到目标，不补播。
- `prefers-reduced-motion: reduce` 时所有移动立即完成。
- 静止时不重绘（`frameloop="demand"`），动画进行中才持续渲染。

## 回退与偏好

- 偏好存于现有偏好键加 `:view` 后缀的独立键（`"3d" | "flat"`），不放进 quick/keyboard 那份 JSON，以免现有写入方覆盖它，在“牌桌偏好”设置中提供“3D 牌桌”开关。此开关与“快速出牌”等四项开关不同：在支持 WebGL 的设备上默认开启。
- 自动回退到平面牌桌的情况：WebGL 不可用、上下文创建失败或丢失后无法恢复、懒加载失败、竖屏、持续低帧率（`PerformanceMonitor` 判定后提示一次并切换）。
- 回退只换牌桌展示组件，不重建对局连接，不丢失选牌与提交锁状态（状态本就在控制器中）。

## 第一期实现记录（2026-11-11）

- 依赖：`three@0.186.1`、`@react-three/fiber@9.8.2`、`@types/three@0.186.0`（固定版本）。未引入 drei：圆角牌体用 three 自带的 `RoundedBoxGeometry`。
- 文件：`frontend/src/table3d/`（`layout.ts` 纯布局、`textures.ts` 牌面图集与中央局况、`geometry.ts` 牌体、`Table3D.tsx` 场景与 HUD、`table3d.css`），`TableView.tsx`（3D/平面选择与回退），`PlayerPlate.tsx`，`tile-glyphs.ts`（平面与 3D 共用牌面几何）。
- 布局尺寸：河起点距中心 3.55、牌墙 10.3、手牌 12.3、桌半宽 14.6（单位为牌宽）；`tests/table3d-layout.test.ts` 校验早局与满副露后期任意两张牌不相交、隐藏牌无 ID、公开牌 ID 唯一。
- R3F 9.8 在本页首次加载时，react-use-measure 的首次尺寸回报会被丢弃，画布停在 300×150 直到下一次布局变化。`Table3D` 挂载后派发一次 `resize` 解决；Canvas 的 `gl`/`camera`/`dpr`/`onCreated` 保持恒定引用，且 `Table3D` 只在 `view` 变化时重渲染（对局页每 200ms 刷新倒计时）。
- 卸载画布会主动触发 `webglcontextlost`，只有在显示期间的丢失才记为失败并回退平面。
- 开发：`frontend/vite.config.ts` 支持 `MJ_API_PORT` 指定后端端口（默认 3000）；`.claude/launch.json` 新增 `mahjong-backend-3d`（端口 3013，独立库 `data/3d-preview`）与 `mahjong-ui-3d`。

## 第二期实现记录（2026-11-11）

- 本家手牌在场景中放大 1.32 倍、后仰约 41° 朝向镜头，立于近侧桌沿内（`SELF_HAND`）；选中牌沿牌面上方抬起，可出牌之外的牌在本家行动时变暗。副露仍按实物大小平放在右侧桌角。
- `hand-anchors.ts`：场景把每张手牌牌面（含抬起后的位置）投影成屏幕矩形，发布到一个小型订阅仓库；`Game.tsx` 用 `useSyncExternalStore` 读取，给原有手牌按钮写入 `left/top/width/height`。按钮本身、`data-hand-tile`、`aria-pressed`、禁用状态、指针手势、键盘与焦点逻辑都未改。
- `Game.tsx` 用 `.play-stage` 包住牌桌与操作区；只有锚点就绪时才加 `.stage-3d`，此时 `.hand-rack` 叠在画布上：手牌按钮透明（焦点外圈仍可见），操作行贴在手牌上方右侧，本家信息牌贴在手牌上方左侧，`hand-footer` 隐藏。平面模式与 3D 加载期间结构和外观不变；3D 卸载时清空锚点。
- 操作区获得焦点时，焦点外圈画在 3D 牌桌上，而不是画布下方剩余的设置区。
- 本地验证：真实对局中点 3D 手牌后点「打出」；`tests/v42-browser-fixture.tsx`（在浏览器面板中手动打开）中验证立直（仅可立直牌高亮、`riichi-16` 只提交一次）、碰（选择弹窗在 3D 上方、`pon` 只提交一次）、键盘方向键选牌加 Enter（`discard-4`）、Tab 焦点外圈落在 3D 牌上，以及 1440×900、1280×720、844×390 与竖屏回退。`pnpm test:table:browser` 因本机无 Playwright 未运行。

## 第三期实现记录（2026-11-11）

- 每张牌一个 `TileMesh`，按 `t<牌ID>` 保持身份；变换由组件内的补间驱动（不再由 props 直接定位）：目标变化时按三次缓出移动，时长 0.13–0.46 秒随距离增加，跨桌飞行带抛物线高度。选中牌抬起也走同一补间。
- 新出现的牌按来源起飞：他家打出或鸣出的牌从该家手牌处飞出（立直宣言牌途中转为横放）；摸牌从上方落入；新翻开的宝牌原地翻面；局终公开的手牌从立起状态倒下（`lastHandResult.revealedHands`，仅在本局 `HAND_RESULT` 期间显示）。
- 直接定位不补播：首次显示、换局（`handId` 变化）、一次更新中换组或换座的牌超过 6 张（`isJump`，重连、补同步或多步合并）、以及系统开启“减少动态效果”。
- 补间按真实时间计算；页面在后台时 `requestAnimationFrame` 暂停，回到前台的下一帧即到终点，不会卡在半路。
- 开发构建中 `window.__table3d` 暴露 R3F 状态，牌对象以 key 命名，便于在控制台逐帧检查；生产构建不含此钩子。
- 本地验证：真实对局中逐帧推进（`advance`）采样，他家首打从其手牌处经弧线落入牌河，本家打牌从手牌飞入牌河；`isJump` 与公开手牌有单元测试。未验证：可见窗口下的肉眼观感（浏览器面板处于隐藏状态，`requestAnimationFrame` 不运行）、减少动态效果开关、真实断线重连时的跳过。

## 第四期实现记录（2026-11-11）

- **一张牌一次绘制**：牌面字形不再是叠在牌体上的单独平面，而是按 UV 直接映射到牌体正面的平坦区域（该区域正好 0.84 宽，与字形区一致），面层颜色取自贴图集、背层取自顶点颜色。每种字形缓存一份合并几何体。1440×900 下一帧从 368 次绘制降到 281 次（含阴影通道），三角形约 16.3 万，本机一帧约 0.8 ms。未做实例化：在此规模下收益不大，且会让按牌 ID 的补间复杂得多。
- **上下文丢失**：丢失后先等浏览器恢复（3 秒）；恢复后 three.js 重新上传资源并重绘，牌桌照常；超时未恢复才改用平面并提示。两条路径都用 `WEBGL_lose_context` 实测过。
- **自适应画质**（`quality.ts`）：只在牌移动、连续出帧时统计帧间隔（忽略 4 ms 以下与 250 ms 以上，排除空闲与后台节流）；满 24 帧时中位数超过约 1/28 秒即降一档：像素比 2 并开阴影 → 1.5 并开 1024 阴影 → 1 并关阴影；最低档仍慢则改用平面，并提示“在这台设备上运行较慢，可在上方改回 3D”。以 60 ms 间隔手动推进帧验证了逐档下降与回退；16 ms 间隔不降档。
- **画布比例**：画布高度不超过宽度的 1/1.45（`.play-stage` 容器查询单位），宽屏上不再在手牌下方留空。

## 未决与风险

- 拖动出牌手势在透明按钮边界上的手感，需要真机触屏试用。
- 手机横屏下手牌约 24px 宽，可读但偏小；如需更大，可考虑在窄高画布上单独放大手牌或裁去对家一侧桌沿。
- 3D 代码按需加载，压缩后约 257KB；构建时“chunk 超过 500KB”的警告指的就是这个包，不影响首页。
- 回放的 3D 化不在本次范围。
