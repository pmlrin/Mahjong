# 对局状态与通信协议 v2.0

规则仍为 `riichi-4p-v1.0`；实时与 HTTP 契约升级为 2.0。原协议的实体牌编码、个人快照、合法 optionId、幂等回执、单一控制连接、隐藏信息隔离与 15／8／8 秒时限继续适用。本文和共享类型、运行时 Schema、测试一起维护。

## 能力与版本

`GET /api/v2/capabilities` 无需认证，返回程序版本、protocolVersion、支持的赛制、AI 等级、时限、保存策略及维护状态。Socket.IO auth.protocolVersion 必须为 2.0。旧实时客户端明确收到 PROTOCOL_UNSUPPORTED／请刷新，旧 HTTP /api/v1 端点返回 426；旧牌谱协议 1.0 由回放适配器读取，不重新计分。

## 房间与准备轮次

Room 增加 lobbyGeneration（初始 1）、previousMatchIds、isRematchLobby、memberJoinOrder、offlineSince。所有等待厅修改请求（包括离开、准备、机器人、配置、开始）携带 lobbyGeneration；既有 expectedRoomVersion 仍校验版本。删除机器人的轮次与版本使用请求头 Lobby-Generation、ExpectedRoomVersion。过期轮次返回 LOBBY_GENERATION_CONFLICT，原数据不变。

- `PUT /rooms/:roomId/config`：format、lobbyGeneration、expectedRoomVersion。
- `POST /rooms/:roomId/rematch`：lobbyGeneration、expectedRoomVersion；仅房主且原比赛 FINISHED。原子把 room 变 WAITING，轮次加一、matchId=null、旧 ID 放入历史引用、清空真人准备。
- 原房间／邀请码／位置与机器人等级保留。下一场开始时创建全新 matchId、初始座位、25000 点及全部窗口。
- 清位只发生在再战等待厅；离线满 30 秒清位，重连取消、再次离线重新计时。房主转交按 memberJoinOrder，非按空槽编号。进行中不清位。
- 当前房间成员不自动获得旧场权限；gameFor 与历史端点始终查比赛冻结成员。

## 比赛配置

MatchState／MatchView 固定保存 format、mode（AI_PRACTICE／FRIENDS）、protocolVersion、botPolicyVersion；mode 按开场真人数确定。半庄计划为东／南，西为延长；东风南为延长。AI 成员保存 BASIC／STANDARD 及策略版本；真人托管固定 STANDARD。

## 本人历史与统计

- `GET /history?format=&mode=&cursor=`：每页 20 条，按 finishedAt DESC、matchId DESC；游标绑定时间和 ID，同时间不漏项。返回摘要和 nextCursor，不返回完整状态或牌山。
- `GET /matches/:matchId`：参与者读取已结束／中止的成员、成绩、逐局摘要、回放可用性。进行中使用 game:attach。
- `GET /stats?format=&mode=&days=30`：只统计本人且正常 FINISHED；返回 N、一位率、平均顺位、各名次数量／比例及平均净得失；N=0 的比例与均值为 null。
- 独立 SQL 历史摘要及 userId 索引，不在查询时扫描和解码全部比赛。摘要 matchId 唯一；成员及分数来自冻结比赛快照。内部模拟不得写入本人战绩。

## 回放与观看位置

牌谱导出新版本 2.0，仍支持旧版 1.0；只从已记录事件重建。事件顺序为稳定索引，配对 handId 验证。

- `GET /matches/:matchId/replay-position`：本人位置或 null。
- `PUT /matches/:matchId/replay-position`：handId、eventIndex、viewerSeat；校验参与资格、FINISHED、事件所属局和范围后保存。全信息开关不保存、不默认恢复。
- 关键事件：立直声明／成立、吃碰成功、候选／成功杠、和牌／流局。定位及恢复不执行规则动作，不把候选杠当成功杠。

## 诊断

`POST /diagnostics` 接收可选 roomId／matchId，校验成员后生成 diagnosticId、服务版本、协议／规则、阶段及安全可见序号。服务端以该 ID 记录同一时段 match／hand 的日志锚点；复制白名单输出，不包括身份凭据、bindingId、手牌、牌山或私有选择，不自动外发。

## 持久化与迁移

新增 history_summaries、history_members、replay_positions、migration_issues。正常关局产生终局时，摘要／成员索引与状态在同一事务写入；以 matchId 唯一且幂等更新。旧场回填保留原结果与事件，明确标记 legacy 来源；缺少成员、非法排名、点数不守恒等进入异常清单，不猜测成绩。迁移只增结构，不覆盖原始比赛。

## 发布与回滚

先保存旧发行包与数据库备份，在副本验证迁移与重跑。维护时阻止新开始，等待 RUNNING 数为零后切换；不强制中止。新赛制／再战写入后旧程序不再作为安全回滚目标，优先使用能读取 v2 的修复版本。只有未发生新写入且验证时间点时才可恢复发布前快照。真实手机、容量、逐条规则证据分别见 V2 验收记录，不以代码存在宣称通过。
