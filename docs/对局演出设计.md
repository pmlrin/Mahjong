# 对局演出：设计方案

日期：2026-11-12
状态：四期均已实现（事件层、音效、出牌落桌；宣言印章、立直棒；和牌与流局演出；收尾与验证），见文末实现记录
前置：[3D 打牌视角设计](3D打牌视角设计.md)、`DESIGN.md`（靛染设计系统）

## 已确认的决定

| #   | 决定     | 内容                                                                                                              |
| --- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| 1   | 宣言样式 | 印章：方形朱印，写「吃／碰／杠／立直／荣／自摸／流局」，落在宣言者信息牌旁，盖下后约 0.8 秒淡出。无发光、无粒子。 |
| 2   | 音效     | 继续由 Web Audio 合成，不引入录音素材；沿用现有开关，默认关闭。                                                   |
| 3   | 和牌演出 | 约 2 秒后进入现有结算面板，不改服务器的 8 秒展示；可点击跳过。                                                    |
| 4   | 平面牌桌 | 宣言印章与音效同样生效；落桌动作与和牌演出只在 3D。                                                               |

不做：人物胳膊和手、角色语音、画面震动、回放演出（以后复用事件层）。

## 约束

- 服务器只下发完整快照（`MatchView`），没有“刚发生了什么”。事件由前端比较前后两次快照得出，与 3D 飞牌同一思路。
- 演出不延迟服务器、不占用操作时间、不拦截输入。行动按钮与倒计时照常。
- 单局结算展示由服务器固定 8 秒（`resultDisplayUntil`）；和牌演出只占用其中开头。
- 断线重连、重新同步、一次变化过多（跳变）时只显示最新状态，不补播。减少动态效果时不播动作（印章改为静态短暂显示）。

## 事件层

`frontend/src/match-events.ts`，纯函数 `matchEvents(before, after)`，返回按发生顺序排列的事件，或 `null` 表示跳变（不播）。

| 事件           | 判定                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| `discard`      | 某家牌河在原有基础上新增的牌（discardId 前缀一致）；带牌 ID、摸切、立直宣言牌                                      |
| `call`         | 新出现的吃／碰／大明杠副露；暗杠、加杠以 `pendingKan` 首次出现时为准（之后落成不重复），若错过该帧则以副露落成补报 |
| `riichi`       | 立直状态 NONE → DECLARED（宣言）                                                                                   |
| `riichi-stick` | DECLARED → ESTABLISHED（立直棒入场）                                                                               |
| `dora`         | 宝牌指示牌数量增加                                                                                                 |
| `win`          | 同一局进入 HAND_RESULT，`lastHandResult.wins` 每家一条（荣和／自摸／流局满贯）                                     |
| `draw`         | 同一局进入 HAND_RESULT 且无和牌：荒牌流局与各途中流局                                                              |

跳变：matchId 或 handId 改变（新局只做开局摆放）、某家牌河或副露不是在原有基础上追加、单次事件超过 6 个。

## 分期

1. **事件层、音效、出牌落桌**：事件层与单测；合成音效（出牌、鸣牌、立直宣言、立直棒、宝牌、和牌、流局）替换现有“嘀”；3D 中出牌改为“抬起—空中稍停—落下”，落桌声与落下时刻对齐。
2. **宣言印章与立直棒**：3D 与平面共用 DOM 印章层；立直棒从宣言者滑入桌心；读屏礼貌播报。
3. **和牌与流局演出**：停顿、手牌倒下、和了牌抬起高亮、立直和牌翻里宝牌，约 2 秒后出结算；剩余展示时间不足 4 秒时不播；可点击跳过。
4. **收尾与验证**：减少动态效果、跳变、断线重连、低端降档下的表现；截图与记录。

## 音效

全部由 Web Audio 合成，音量与原“嘀”相当（峰值增益约 0.04–0.06），每类一个固定音色：

| 事件     | 音色                                    |
| -------- | --------------------------------------- |
| 出牌     | 短促木质「嗒」：带通噪声 + 低频短促正弦 |
| 鸣牌     | 上行两音                                |
| 立直宣言 | 低音长一些的单音                        |
| 立直棒   | 清脆「咔」                              |
| 宝牌     | 轻高音                                  |
| 和牌     | 柔和三音和弦                            |
| 流局     | 下行两音                                |

3D 牌桌在播放落桌动作时，出牌声延迟到牌落下的时刻；平面牌桌、减少动态效果或跳变时立即（或不）播放。

## 素材登记

不新增外部素材。音效为本项目 Web Audio 合成；印章为 CSS 与系统字体。

## 第一期实现记录

- **事件层**：`frontend/src/match-events.ts`。同一步内多家变化按“立直宣言 → 出牌 → 鸣牌 → 立直棒 → 宝牌 → 结果”排序。流局满贯同时给出 `win`（方式 `NAGASHI_MANGAN`）与 `draw`。
- **音效**：`frontend/src/sounds.ts`，替换 `main.tsx` 原“嘀”。由 `Game` 比较前后两次 `MatchView` 触发；同一步内同类声音只响一次；跳变不响。开启音效时以出牌声试听。
- **出牌落桌**：`Table3D` 中进入牌河的牌（对手从手牌位置、本人从手牌原位）走固定 0.46 秒路径：先升到落点上方 0.55 处并平移（不上抛），悬停略降，再加速落下。时间常量在 `frontend/src/table3d/timing.ts`，不引入 three.js，页面据此把出牌声延后到落下时刻。其它移动（鸣牌入副露、摸牌、宝牌翻开）不变。
- **测试**：`tests/match-events.test.ts` 6 项。其中 6 场 AI 东风战逐步投影（28 局、1404 次出牌、吃碰暗杠、立直、荣和、自摸、流局）每一步都识别为连续事件，且每局累计数与终局牌面一致；另测新局、新比赛、改写历史、超量变化、立直顺序、杠只报一次。
- **验证**：`pnpm build` 通过；`pnpm test` 173 项通过（第一次运行有 4 项失败，未保存输出，随后三次全量运行均通过，未能复现）。预览环境 1280×800 实测：对手与本人出牌轨迹为“升至 0.94 → 悬停降至 0.80 → 落至 0.39”，历时 0.45–0.47 秒；3D 下出牌声排定在 0.465 秒后，平面牌桌下 0.005 秒；无新的控制台错误。
- **未验证**：实际听感（本环境无法收听）、Safari 的 Web Audio、手机上的帧率与音频延迟。

## 第二期实现记录

- **事件共用**：`Game` 每步只算一次事件（`PlayStep`，带递增编号），印章与音效共用；音效关闭时印章照常。
- **印章**：`frontend/src/CallStamps.tsx` 与 `stamps.css`，放在牌桌外框（`.table-frame`）内的 DOM 层，3D 与平面牌桌共用。吃／碰／杠单字；立直、自摸两字竖排；流局在桌心，途中流局附原因（九种九牌等），荒牌流局不附。流局满贯只盖「流局」。同一座位的新印章替换旧的；1.15 秒后移除，动画为放大落下、略回弹、停留后淡出；减少动态效果时只显示后淡出。自家印章在手牌上方：3D 用手牌顶边，平面牌桌用牌桌底边向上 64 像素。
- **读屏**：印章层内一行 `aria-live="polite"` 隐藏文字，例如「秋山 立直」「你 碰」「四风连打」；不播报出牌。相同内容连续出现时末尾加零宽空格，使其仍被读出。
- **立直棒**：3D 中改为立直成立（ESTABLISHED）后才出现，与「立直棒」音效同时；从宣言者一侧离桌面 0.35 处滑入桌心，0.36 秒减速。首次显示、跳变、减少动态效果时直接放好。
- **荣和与自摸印章**：已经盖下，但结算面板目前在同一时刻弹出并遮住，第三期延后结算面板后才可见。
- **验证**：`pnpm build` 通过；`pnpm test` 173 项通过。期间一次全量运行中 `tests/network.test.ts` 的两项集成测试（超时回执落库等）失败，单独重跑该文件两次与之后全量运行均通过；本期未改后端，判断为负载下的偶发失败。预览环境 1280×800 真实 AI 对局中观察到：白露「吃」（左侧）、白露「荣」、秋山「立直」（对家，两字竖排）及读屏文字；对家立直棒从 z=−5.65、高 0.34 滑向桌心。另用静态副本检查五个位置在 3D 与平面牌桌上的摆放，修正了平面牌桌自家印章压住牌河中央的问题。新标签页加载无控制台错误。
- **未验证**：实际观感节奏（本环境截图为静止画面）、手机横屏下的印章大小、读屏软件实际朗读。

## 第三期实现记录

- **牌面**：`table3d/layout.ts` 中结算时和了牌标记 `winning`，3D 里抬高 0.45 并显示高亮标记；立直和牌的里宝牌翻开后摆在王牌前方一排（背面占位保留）。新增 `handResult(view)` 统一取本局结果。
- **节奏**：常量在 `table3d/timing.ts` 的 `REVEAL`。进入结算后停顿 0.3 秒，各家手牌每张间隔 0.035 秒依次倒下；和了牌 0.85 秒时抬起；里宝牌 1.05 秒起每张间隔 0.12 秒翻开。跳变与减少动态效果时直接放好。
- **延后结算面板**：`Game` 在出现和牌或流局事件时，若服务器剩余展示时间超过 4 秒，3D 下延后 2 秒、平面牌桌延后 1.2 秒再弹出结算面板（`RESULT_HOLD`），期间荣／自摸／流局印章可见；牌桌顶部有「查看结算」按钮可立即跳过。服务器 8 秒展示不变，重连或剩余时间不足时直接出面板。
- **测试**：新增布局测试「和了牌抬起、立直和牌翻里宝牌」（牌键唯一、只有一张和了牌、里宝牌在王牌区正面朝上、互不重叠）；`pnpm build` 通过，`pnpm test` 174 项通过。
- **验证**：预览环境 1280×800 真实 AI 对局。本人立直自摸：「查看结算」按钮 0 毫秒出现，结算面板 2013 毫秒弹出；和了牌在 861–988 毫秒间抬至 1.46；里宝牌在 1069–1198 毫秒间翻开，落在 0.39；读屏文字「你 自摸」。荒牌流局：听牌对手 11 张手牌依次倒下（结束时刻 427→747 毫秒），读屏「荒牌流局」。新标签页加载无控制台错误（开发中修改 `timing.ts` 触发的热更新会出现 `createRoot` 重复调用报错，仅开发环境）。
- **未验证**：对手荣和时的倒牌过程截图、里宝牌在画面上的实际观感、手机上的节奏与按钮位置。

## 第四期实现记录

- **应用内「减少动画」**：此前只有系统的减少动态效果生效，应用设置里的「减少动画」对 3D 牌桌和出牌声时机不起作用。新增 `frontend/src/motion.ts`：`useReducedMotion()` 同时看系统设置与应用设置（`main.tsx` 在 `Game` 外提供），3D 牌桌与出牌声共用。印章在两种设置下都由全局规则去掉动画，静止显示 1.15 秒后移除；`stamps.css` 中从未生效的减少动态效果分支已删除。
- **断线重连不补播**：`match-events.ts` 新增 `frameEvents(before, after)`。服务器对每位玩家的视图逐帧编号（`viewSeq` 每发一帧加一），只有同一流里紧接着的下一帧才算一步；同步应答帧（重连后的 attach、页面回到前台后的同步，带 `syncId`）、编号有缺口或流变化（服务器重启）的帧只显示不补播。`Game` 改为按帧比较。单测 7 项。
- **自家手牌顶边**：第三期公开他家手牌后，`HandAnchors` 把他家正面朝上的手牌也算进「手牌顶边」，和牌时 `--hand-top` 变成对家手牌位置（约 97 像素），自家印章与「查看结算」会跑到牌桌顶部。现只取自家座位的手牌。
- **「查看结算」位置**：原在对家信息牌下方，手机横屏时与对家的荣／自摸／立直印章重叠（竖屏平面牌桌也略有重叠）。改到自家印章右侧同一行：这一行在任何尺寸下都没有其他印章或信息牌，结算期间自家操作按钮也不显示。印章大小与自家印章离手牌的高度改为 `.table-frame` 上的变量，按钮与印章共用。
- **测试**：`pnpm build` 通过；`pnpm test` 175 项全部通过。
- **验证**（预览环境，真实 AI 对局）：
  - 断线：人为断开牌桌连接约 10 秒，重连后一帧补上 4 张以上出牌，没有出牌声；之后每帧正常各响一次。仅 0.8 秒的短断线没有漏帧，也无补播。
  - 应用内减少动画：出牌声在 0.005 秒响（不再延后 0.465 秒）；新打出的牌在帧到达后 30 毫秒已在牌河落点（高 0.39）且不再移动；印章 `animation-name` 为 `none`。
  - 一场的最后一局（秋山自摸、赛程结束；竹影自摸、飞人终局）同样出现「查看结算」并延后结算，之后照常进入终局结算面板。
  - 位置：在 1280×800（3D）、812×375 横屏（3D 与平面）、375×812 竖屏（平面）下检查印章与按钮：按钮都在自家印章右侧，不压其他印章与信息牌。修正手牌顶边后，自家荣和与秋山（下家）荣和时 `--hand-top` 均保持 578 像素，按钮在自家印章旁。秋山荣和时截图可见其手牌在右侧摊开正面朝上，其他家手牌仍为背面。
  - 降档：用「改用平面牌桌」切换代替自动降档检查，印章层与按钮在牌桌外框内，切换后照常显示。
- **未验证**：实际听感与观感节奏、真机（手机、Safari）上的表现、自动降档发生在演出途中的情形、读屏软件实际朗读。竖屏平面牌桌上自家印章会短暂盖住自家点数（第二期起如此，未改）。

## 牌桌音乐（2026-11-18）

- **方案**：环境底噪加实时生成的五声音阶旋律（`frontend/src/music.ts` 播放，`frontend/src/music-score.ts` 作曲，后者不碰音频，可单测）。D 宫五声（D E F♯ A B），每步一个八分音符、两小节一句，旋律小步游走、句中换气、句尾落在主音上，拨弦音色带上滑音和长音颤音，下垫低音持续和弦，经混响与回声。不循环，所以不会听出重复。
- **随牌局变化**：普通局 `calm`（66 拍，句尾落宫、徵）；有人立直 `tense`（80 拍，转羽调色彩，加心跳低音和每小节低音）；一场的最后一局或延长局 `final`（74 拍，加低音）；和牌、流局、终局结算显示时 `rest`（旋律淡出，只留和弦与底噪）。立直、和牌、流局时音乐压低约 1.6 秒让音效先出（音效开着时）。
- **开关**：页头音符按钮，偏好存 `mj_music`，默认关闭；与音效开关互相独立。只在牌桌页播放，离开牌桌淡出停止；切到其他标签页时暂停。浏览器要求先有点击才能出声，打开音乐后第一次点按页面即开始。
- **底噪**：OpenGameArt 上 Ylmir 的 CC0 实录雨声 Rain (loopable) 第 3 段（45 秒，可无缝循环），`frontend/src/assets/music/ambient.{ogg,m4a}`，来源、选段理由与转换方式见同目录 `SOURCE.md`。按平均响度统一到 0.012；载入前或载入失败时用同样响度的合成雨声代替，两者交叉淡入淡出。实测音乐淡入后整体响度稳定在 0.011–0.014，切到录音时没有掉音量。
- **测试**：`tests/music-score.test.ts` 4 项（局况判定、音阶与音域、句尾落音、结算时静音）。`tsc --noEmit` 通过。
- **验证**（预览环境，AI 对局，在页面里接分析器测输出）：音乐开启后上下文为 running，calm 峰值约 0.06、tense 约 0.09（音效峰值 0.25），压低时降到约 0.02，rest 约 0.035，停止 2.5 秒后输出为 0。页头开关可开可关。
- **未验证**：实际听感（音色、音量是否合适需人耳判断），Safari 与手机真机。

## 牌桌音乐改为固定曲子（2026-11-19）

- **原因**：项目负责人试听后认为实时随机生成的效果不好，要求按文案风格写一段固定的音乐，存成文件直接播放。
- **曲子「灯下」**：按文案方向“雪夜灯下的小魔术”作曲（景清、话暖、偶尔俏皮）。F 大调，72 拍，32 小节约 107 秒，分四段：A 推门点灯，B 炉边坐定，A′ 旋律再现、八音盒叠高八度，C 窗外落雪，音符之间留空。旋律只用五声音 F G A C D，和声为大七、九和弦，每段末尾八音盒点一串亮音，就是那一点“小魔术”。乐谱和合成写在 `scripts/compose-table-music.ts`，随机种子固定，每次生成的文件都一样；成品为 `frontend/src/assets/music/table-theme.m4a`（AAC 160 kbps，1.9 MB），来源与重新生成方法见同目录 `SOURCE.md`。
- **播放**：`frontend/src/music.ts` 把曲子和雨声各自循环播放，按平均响度统一（曲子 0.022，雨声降到 0.006，只作底色）。原来随局况变化的节奏和层次（立直加快、最后一局加低音）随实时生成一起去掉；保留的是：结算显示时音乐退到 55%（`frontend/src/music-mood.ts`），立直、和牌、流局时压低约 1.6 秒，切到其他标签页淡出。开关、默认关闭和只在牌桌页播放都不变。`music-score.ts` 与其测试删除，换成 `tests/music-mood.test.ts`。
