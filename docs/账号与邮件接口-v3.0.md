# 账号与邮件接口 v3.0

程序0.3.0；实时协议仍为2.0，规则仍为riichi-4p-v1.0。所有端点位于现有 `/api/v2/auth/`，修改请求要求 Origin 校验和 UUID Idempotency-Key。密码不trim，长度按Unicode码点12～128计算。

- `register/code`：email、flowId。当前有效游客发起，返回challengeId、expiresAt、resendAt与统一受理说明。
- `register/verify`：challengeId、code、flowId。成功返回grant、expiresAt；只有实际验码成功后才可能返回alreadyRegistered。
- `register/complete`：grant、password、confirmation、flowId。绑定原userId并轮换会话。
- `login`：email、password、flowId、confirmSwitchGuest。切换游客须明确confirmSwitchGuest=true；不合并数据；另一正式账号必须先退出。
- `logout`：flowId。仅撤销当前会话。
- `release-control`：空对象。明确把当前牌局交给AI并释放控制；准备厅则明确离开，身份仍然保留。身份操作的服务端校验不会被前端按钮绕过。
- `password-reset/code`：email、flowId。未知邮箱也返回统一结构，不实际发找回邮件。
- `password-reset/verify`：challengeId、code、flowId。返回受限grant。
- `password-reset/complete`：grant、password、confirmation、flowId。撤销该账号全部旧会话，不自动登录。
- `password/change`：currentPassword、password、confirmation、flowId。撤销旧会话并只签发一个新当前会话。

flowId由浏览器用安全随机源生成，保留在本次页面流程，作为高熵发起上下文；请求不使用URL传递验证码、flowId或grant。注册同时绑定原游客令牌摘要。grant由服务器生成32字节随机值，服务端只保存摘要。

验证码10分钟，重发60秒、同邮箱跨用途冷却；同用途旧挑战失效。每挑战5次错误，跨重发15分钟10次失败。密码登录按邮箱比较键和IP分别限流。邮箱小时5／日20、IP小时20／日100、实际SMTP尝试每日100含重试，持久化到数据库。

敏感请求只持久化HMAC和必要业务结果。验证码验证同幂等键重试可在原上下文、原授权截止内替换grant，旧grant作废；已完成后只返回已提交结果。登录响应丢失时重新验证密码后签发新令牌，数据库不重放明文Cookie。注册／重设完成后响应丢失返回已完成并引导登录。

`me`保留userId、displayName、roomId、matchId，增加identityKind、maskedEmail。能力增加auth.enabled、passwordLogin、registration、passwordReset、mailAvailable、previewRestricted，不公开SMTP秘密、白名单地址或账号是否存在。

旧会话迁移保留userId、有效期和权限。新用户资料与凭据、会话分离；账号关闭入口不降级账号。所有Socket消息在入队执行时再次验证当前会话与认证版本，撤销后停止私有推送。找回导致的断控按原窗口截止和托管规则处理，不清除既有选择、座位或点数。

发信事务只提交QUEUED任务，SMTP在独立异步任务执行；465立即TLS并验证证书，最多重试2次。ACCEPTED仅表示SMTP接受。邮件正文AES-256-GCM加密，终态和过期清除密文。预览白名单与邮件标记独立；没有配置时邮件入口不可用，绝不回显测试验证码。
