## 首次安装

先在本地 `pnpm build` 并执行 `node --import tsx scripts/package.ts`，打包编译结果、运行依赖和 `deploy/`。官方 Linux Node.js 包须核对官方 SHASUMS256；不要用 macOS 的运行包或含 macOS 原生扩展的依赖。

`deploy/install-native.sh` 只用于新安装，会拒绝覆盖已有 Mahjong 服务、秘密文件或 Nginx 站点。该脚本里的版本目录为初次部署的固定版本；后续使用下述更新方式。数据库复用服务器已经存在的官方 PostgreSQL 17 镜像，不接入其他网站的数据库。

运行包可用 `node --import tsx scripts/prepare-release.ts <打包目录>` 准备；然后在该目录执行 `pnpm install --prod --ignore-scripts --frozen-lockfile`。运行依赖与锁文件保存在发行包中。

## 更新与回滚

每次都使用新的版本目录，保留旧发行包和旧目录。上传前先验证目标路径不存在。

1. 本地执行固定测试、联机测试、完整模拟和构建。
2. 生成新版本的编译包；运行依赖变更时同时更新依赖锁。
3. 备份数据库；解包到 `/opt/mahjong/releases/<新版本>/`。
4. 确认新目录权限可供 `mahjong` 用户读取，且配置仍引用原来的环境文件。
5. 原子切换 `/opt/mahjong/current` 软链接，重启 **mahjong.service**。
6. 验证健康检查、日志、已有游客恢复、epoch 更新与正式域名实际操作。

回滚：把 `current` 指回上一个兼容版本，重启麻将服务并验证。修改数据库结构或事件格式前应单独设计兼容迁移，不能假定任意旧程序都能读取新状态。更新不删除卷、不执行 `docker compose down -v`，不更改其他站点。

## 备份

```sh
bash /opt/mahjong/current/deploy/backup.sh
```

备份位于 `/opt/mahjong/backups/mahjong-<UTC时间>.dump`，权限受 umask 077 保护。每日自动备份由 `mahjong-backup.timer` 启动，计划时间为东京时间 04:00。备份尚未自动同步到异机，需定期人工复制到安全的备份位置；同机备份不能覆盖磁盘整体损坏。

## 恢复验证

在不替换生产数据库的前提下，创建隔离的临时数据库，把备份通过 `pg_restore` 恢复进去，比较 documents 的行数与按主键排序后的数据摘要。这项验证与备份文件是否存在分别记录。

真正回滚生产数据前，先停止麻将写入、保留当前库备份，确认目标备份时间与恢复影响。不能把旧备份导入正在运行的库，否则可能破坏动作回执与结算的一致性。使用隔离库验证后再执行明确的切换计划。

## 数据与规模边界

当前采用单服务写入，PostgreSQL advisory lock 防止两个麻将进程同时作为写入者。所有有效操作按队列处理；状态、回执、投影及最新发件箱在同一数据库事务中提交，提交后推送。重连读取完整快照。

当前没有自动清理比赛的任务；正常比赛与牌谱至少保留 30 天，中止资料至少保留 7 天。引入清理前必须覆盖回执、成绩、牌谱入口和备份的完整生命周期。生产 10 桌容量与多机高可用不能从本地模拟结果推断。

## 次版隔离预览与正式维护切换

0.2.0 的 `/preview/` 使用独立服务、库和 `mj_preview_session` Cookie，不能接入正式数据库做模拟。独立入口仅用于预览，不表示《次版功能范围》全部验收通过。已运行的短时十桌压测不代替真机、长时间压力或公网线路测试。

预览构建使用 Vite `--base=/preview/`。前端从 BASE_URL 生成 API、Socket.IO 和邀请链接路径；后端可设置 STATIC_DIR、SESSION_COOKIE_NAME、SESSION_COOKIE_PATH。Nginx `/preview/` 反向代理会去掉此前缀，保留 WebSocket 升级、Host 与 HTTPS 转发。正式根路径的服务、Cookie、库与证书不变。

正式发布须先完成当前验收待项；停止新开场，等待所有 RUNNING 比赛自然结束，保存旧包与数据库备份，在副本迁移及重跑验证后才切换。0.2.0 支持 MAINTENANCE_FILE 阻止新开始，已有比赛继续运行。0.1.1 需用独立 Nginx 开场端点维护拦截；不能直接重启清掉活动比赛。

离线迁移入口为 `dist-server/backend/src/migrate.js`，添加 `--rebuild` 重建摘要。持有同库写锁时拒绝第二个进程。migration_issues 要独立处理，不补造成绩。只增加摘要结构、且无V2比赛写入时，旧版回滚已在备份副本验证；一旦半庄／再战已写入，旧版不能直接接管，优先修复V2，禁止恢复旧快照抹除新成绩。

2026-10-29 时独立预览服务 mahjong-v2-preview.service 位于 20261029-v2-rc3，监听127.0.0.1:18031；库 mahjong_v2_preview_20261029。每日04:10 Asia/Tokyo由独立备份计时器生成快照，2026-10-29已实际恢复至另一个测试库并验证迁移重跑不改原始比赛。详见 reports/v2-deployment.json。所有容量／回滚临时服务均已停止。
