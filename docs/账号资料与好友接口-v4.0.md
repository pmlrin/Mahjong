# 账号资料与好友接口 v4.0

程序 0.4.0，规则 riichi-4p-v1.0，麻将实时协议保持 2.0。社交 Schema 独立为 1。沿用 `/api/v2`、Cookie、Origin 校验和 `{data: ...}`／`{error: ...}` 包裹；不创建第二套认证。

## 共享校验与权限

运行时 Schema 和响应类型在 `shared/social.ts`。所有接口要求有效正式账号，会话在执行时再次查询权威记录。修改使用 UUID `Idempotency-Key`，同键异载荷返回 REQUEST_ID_CONFLICT；设备操作额外绑定当前会话。回执只存载荷 HMAC 和固定结果，不保存密码或密码验证结果。查询响应均为 `Cache-Control: no-store`。

昵称先拒绝控制／双向控制字符，再 trim、NFC 规范化，按码点 1–16。头像只能提交预设 ID。好友码忽略首尾空白、连字符和 ASCII 大小写，须为指定字符集中的完整12位；不是邮箱、昵称或六位房间邀请码。

## 端点

| 方法／路径 | 输入 | 成功 data |
| --- | --- | --- |
| GET /profile | 无 | friendCode、displayName、avatarId、profileVersion、lastNicknameChangedAt、serverTime、avatars |
| PATCH /profile | displayName、avatarId、expectedProfileVersion | updated、profileVersion |
| GET /auth/sessions | 可选 cursor | items、nextCursor、serverTime；每页20条有效会话 |
| POST /auth/sessions/revoke | sessionId、currentPassword、flowId(UUID) | revoked:true |
| POST /auth/sessions/revoke-others | currentPassword、flowId | revoked:true |
| GET /social/snapshot | 无 | friends、receivedRequests、sentRequests、receivedInvitations、sentInvitations、counts、revision、serverTime、presenceEpoch、presenceSeq |
| POST /friends/lookup | friendCode | friendCode、displayName、avatarId、relationship |
| POST /friend-requests | friendCode | requestId、state、version；重复返回既有申请，已是好友返回 alreadyFriends:true |
| POST /friend-requests/:id/accept | expectedVersion | requestId、state:ACCEPTED、version |
| POST /friend-requests/:id/reject | expectedVersion | requestId、state:REJECTED、version |
| POST /friend-requests/:id/cancel | expectedVersion | requestId、state:CANCELED、version |
| DELETE /friends/:friendCode | 空对象 | deleted:true |
| GET /blocks | 可选 cursor | items、nextCursor；每页20条，游标为好友码 |
| POST /blocks | friendCode | blocked:true |
| DELETE /blocks/:friendCode | 空对象 | blocked:false |
| POST /room-invitations | recipientFriendCode、roomId、lobbyGeneration、expectedRoomVersion | invitationId、state、version |
| POST /room-invitations/:id/accept | expectedVersion | invitationId、state:JOINED、version、roomId |
| POST /room-invitations/:id/decline | expectedVersion | invitationId、state:DECLINED、version |
| POST /room-invitations/:id/cancel | expectedVersion | invitationId、state:CANCELED、version |

示例：`POST /friend-requests` 发送 `{"friendCode":"ABCD-EFGH-JKLM"}`，成功为 `{"data":{"requestId":"<UUID>","state":"PENDING","version":1}}`。对方接受用产品 requestId 放在路径，HTTP 幂等键另取 UUID，不混用。

会话 items 只含专用随机 sessionId、current、browser／os 大类、createdAt、expiresAt、lastSeenAt；历史缺省时间为 null。没有 token、hash、Cookie、完整 User-Agent、IP 或位置。查找不返回 userId、邮箱、在线状态或房间。好友只增加状态，没有对方历史或私有牌局权限。邀请卡片不包含邀请码和 roomId；只有主动接受成功才返回本人已加入的 roomId。

relationship 为 SELF／FRIEND／INCOMING／OUTGOING／NONE。好友状态为 WAITING／ONLINE／PLAYING／OFFLINE，排序按此顺序再按昵称与稳定好友码。counts 计算收到的有效待处理申请与邀请，打开页面不清零。

## 事务、同步与错误

邀请接受在游戏串行调度内一次提交：重新校验好友／屏蔽、邀请截止、房主、轮次、空槽和其他占位，写房间、准备状态、邀请终态、回执和 revision，提交后更新内存并通知。已在目标房间不重复占位或清除准备；不会移除 AI、自动开场或自动接管。提交不确定时重读权威账号和房间，再重试同一幂等键。

`social:changed` 只通知有权会话刷新，含本人 revision、categories 和进程 presenceEpoch／presenceSeq。消息不作为状态事实；前端合并刷新，并在重连、页面重新可见及每30秒查询完整快照。旧身份的回调不安装数据。后台房间失效通知至多等待下一次3秒周期，断线缓冲最多30秒，撤销不缓冲。关闭推送仍能按快照恢复。

| 错误码 | 含义 |
| --- | --- |
| UNAUTHENTICATED / ACCOUNT_REQUIRED | 会话失效／需要正式账号 |
| INVALID_PAYLOAD / INVALID_FRIEND_CODE | Schema 或好友码格式不合法 |
| FEATURE_DISABLED | 相应能力关闭 |
| PROFILE_VERSION_CONFLICT | 资料版本变化，刷新后重试 |
| PROFILE_CHANGE_IN_ROOM / NICKNAME_COOLDOWN | 仍占位／改名未满24小时 |
| CURRENT_SESSION_NOT_ALLOWED / PASSWORD_INVALID | 不能撤销当前会话／当前密码错误或已变化 |
| NOT_FOUND | 资源未知或无权；屏蔽与不存在的查找反馈一致 |
| SELF_NOT_ALLOWED | 不能添加、删除或屏蔽自己 |
| REQUEST_STATE_CONFLICT | 终态、版本或邀请已变化 |
| FRIEND_LIMIT_REACHED / REQUEST_LIMIT_REACHED | 好友／待处理申请上限 |
| INVITATION_LIMIT_REACHED / BLOCK_LIMIT_REACHED | 邀请／屏蔽上限 |
| SOCIAL_COOLDOWN / SOCIAL_RATE_LIMITED | 冷却／滚动限流，429 含 retryAfter 与 Retry-After |
| ALREADY_IN_ROOM / ROOM_FULL | 另有占位／目标已满；不隐式离房或腾位 |
| ROOM_VERSION_CONFLICT / LOBBY_GENERATION_CONFLICT | 房间配置版本／准备轮次变化 |

产品状态终结后不复活。过期在操作和读取时检查，不依赖清理任务；相同成功操作重试仅返回原结果，客户端仍查询当前房间。
