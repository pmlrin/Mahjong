# 第四版配置与迁移 v4.0

V4 不引入邮件、短信、文件存储或其他外部服务。继续使用原 SMTP、会话密钥、数据库和两个环境的隔离。程序 0.4.0，Node 24.7+；示例 `.env.social.example` 不含秘密。

## 能力与限制

PROFILE_EDITING_ENABLED、SESSION_MANAGEMENT_ENABLED、FRIENDS_ENABLED、FRIEND_INVITATIONS_ENABLED 默认为开启，设 false／0 可关闭相应入口和新操作。SOCIAL_PUSH_ENABLED=false 关闭刷新推送，数据库授权与定期快照仍有效。关闭能力不删除已有资料、关系或会话，不影响原有登录和麻将。

能力接口返回上述四项布尔能力、socialSchemaVersion=1 和可公开 limits。限流环境变量见示例，支持在规格硬上限内下调；不能为压力测试放宽全站基础限流。限流／冷却存于数据库，按滚动时间判断；错误响应含 retryAfter。昵称24小时、申请7天、邀请5分钟、断线缓冲30秒保持规格基线。

social_audit 可按 event／result／时间统计成功、拒绝、限流和入房失败原因；只含内部账号标识，不记录密码、令牌、hash、邮箱、完整 UA 或任意附言。待处理数量由有效 PENDING 行计算，social_user_state 保存提交 revision。客户端通知与快照的收敛由隔离负载工具记录，不把通知当持久事实。

## 迁移与恢复

新增11张表：social_profiles、social_user_state、social_sessions、friendships、friend_requests、blocks、room_invitations、social_cooldowns、social_limits、social_receipts、social_audit。连同原表共28张。可审查 DDL 为 `backend/migrations/004_social_v4.sql`；不能只执行 DDL 而漏掉好友码和历史设备元数据分配。

迁移入口为 `node dist-server/backend/src/social/migrate.js`，源码用 `node --import tsx backend/src/social/migrate.ts`。它复用环境标识与单写者锁，给既有正式账号分配随机唯一好友码，给历史账号会话分配独立 sessionId；历史设备类别 UNKNOWN、创建和最近活动为 null，不伪造登录时间。新注册在原事务内分配好友码，新登录／改密会话在签发事务内记录大类元数据。用户、邮箱、原会话和旧比赛不改写。

工具输出迁移前后 session／room／match 文档摘要与账号数量，不输出凭据。启动也会幂等执行迁移；运行服务持有同库写锁时，离线迁移应拒绝第二个写者，不能同时运行。正式备份恢复副本使用 production 环境，不能修改 auth_environment 让正式副本冒充预览。

正式更新流程：先在正式备份副本迁移、重跑和恢复，再部署隔离预览并完成双账号实际验收；之后按维护流程阻止新开场、等待比赛结束、停服备份、迁移、切换和核验。正式与预览的账号、好友码、关系、设备和数据不互相导入。

本次发布于 2026-11-02 按用户“第四版直接正式上线吧”的明确指令执行。实际维护、备份、迁移和正式核验已完成，真实双账号与真机分项仍标记待补，见[第四版正式上线记录](第四版正式上线记录-v4.0.md)。正式继续加载原认证配置和 `mj_session`、`/` Cookie，新增运行覆盖为 `v4-production-runtime.env`；不将预览收件白名单带入正式。

全库 pg_dump 已包含新增表；数据库与配置秘密分别受限备份。恢复演练逐表比较行数和摘要，不能只看备份文件存在。新版本写入资料／好友／成绩后优先前向修复，不用旧快照覆盖新数据，不把旧V3当作兼容所有V4数据的任意回滚路径。

## 清理与负载工具

默认每小时清理一轮，SOCIAL_CLEANUP_BATCH 默认100、单类至多500行，分批可重入。申请／邀请终态及回执至少保留30天，安全审计90天；过期／撤销会话的新增设备元数据30天后可删除，auth_sessions 的撤销语义保留。好友码、好友关系和屏蔽不会自动删除，清理不写房间／比赛。

清理和普通社交／麻将写入共用串行顺序，先将不活跃账号的过期 PENDING 申请／邀请转为 EXPIRED，再按保留期分批删除，提交后提示相关账号重查。迁移按同一权威时钟跳过已超过设备元数据保留期的旧会话，避免重启后把已清理资料重新创建为 UNKNOWN。原 auth_sessions 不删除或恢复有效。

`scripts/verify-social-storage.ts` 只接受空的 mahjong_v4_test_* PostgreSQL 库，或自己创建的临时 SQLite，用合成账号验证唯一性、回滚、邀请与会话撤销，不添加生产验证码旁路，不连接 SMTP。

容量工具仍为 `scripts/load-v2.ts`，设置 LOAD_SOCIAL_LOAD=1，受限 seed／reset 只允许 ALLOW_ISOLATED_SEED=YES 和 mahjong_v4_capacity* 等专用库。新增50个合成账号每30秒交错查询快照，每秒1次合法关系操作，同时读取推送后再查询快照测收敛；正常结束后自动同桌再战维持十桌。记录游戏回执、社交读写、通知至快照、RTT与实际错误。不能称脚本 HUMAN 为真人。

云端发生器必须在另一台机器；复用 V3 的320 MiB内存硬上限、112 MiB堆、OOMScoreAdjust>=900，以及启动宿主可用内存>=450 MiB、低于200 MiB停止的约束。测试报告按真实条件给出，不从本机测试推断2核共享服务器容量。预览或正式真人／真机证据不足时如实保留待验收。
